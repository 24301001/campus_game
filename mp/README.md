# 原地图联机大厅（本机／局域网）

权威页面是项目根目录的 `像素校园_全校地图.html`。`像素校园地图项目/源码/像素校园_全校地图.html` 是其构建源，`_build/_deliver.py` 投递后会把统一登录和联机钩子应用到三份同名原地图。旧的 `像素校园联机版` 目录只是早期样例，不作为入口。

## 启动

1. 使用本机 Python（当前已用 3.9 验证）和 `websockets>=15`。
2. 双击根目录 `启动像素校园.bat`。它先启动原地图大厅，再尝试启动四个原角色服务；角色缺少本机依赖时会显示原因，大厅仍可登录。终端中的 `[就绪]` 表示该角色端口已监听，具体失败原因看 `mp/runlogs/`；全部四个角色是否启动成功以本次输出为准。只看依赖与端口而不启动，可运行 `python mp/launch_local.py --check`。
3. 打开 `http://localhost:3000/`。局域网其他电脑将 `localhost` 换成大厅电脑的 IPv4 地址，并确保防火墙允许 TCP 3000 和 8090。暂不需要公网服务器。
4. 点击“注册”，填写昵称、密码；照片可选。浏览器把照片采样为像素卡通形象，保存的是颜色、发型和配饰参数，原照片不会发给大厅服务。照片无法处理时先用默认形象入校，再到个人中心重做、微调或下载卡通头像 PNG。

服务数据保存在 `mp/lobby.sqlite3`。备份或迁移时请在停止大厅后复制该文件。联机只接受同一大厅账号；NPC 不再显示自己的登录／注册窗口。

退出登录会清空登录表单、当前地图位置、聊天、NPC 内嵌页面与本机角色票。下一位账号从南门进入。公告是全校公共内容，换账号后仍会显示；私聊、个人资料和 NPC 对话按账号隔离。单机游览会在本机大厅建立临时游客会话，并显示“进入食堂”和“退出单机 · 登录”按钮；它仍需本机大厅和食堂服务运行，不提供断网 AI 对话。

## 地图清晰度与形象

地图入口仍是项目原有的 `像素校园_全校地图.html`，三份同名文件由 `mp/integrate_map.py` 同步集成。原地图在“全图／33%”档先绘制到 480×270，再放大到屏幕，所以缩小画面会糊；现在缩小档按屏幕的整数倍提高画布背板分辨率，1× 档仍使用原来的 480×270 像素画法。全图显示的世界范围更大，远处单个像素仍会小于 1× 视图，但建筑细节不会再先被压进 480×270。

室外玩家昵称随地图缩放：全图档缩成极小的五字标签，50% 档使用较小字号并缩短长昵称；标签重叠时优先显示附近玩家。自己的 ID 始终显示，全图档使用较大的 `#ID` 标签。放大后恢复完整昵称，个人中心、公告和聊天中的昵称保持可读。

`mp/look.js` 在浏览器本地按原始宽高比缩放照片，保留竖幅照里的头发与上衣，再定位脸部、提取发色／肤色／上衣色，识别横条纹，估计头发长度和眼镜，用部件拼出 18×30、脚点 (9,27) 的四向像素小人。侧面是单眼、凸出的鼻尖和后脑；左行面朝左，右行镜像。24×24 头像直接取同一精灵的头肩区域；个人中心、公告和聊天共用该配方。个人中心可改发型、眼型、瞳色、配饰、衣服样式及颜色，并可恢复默认。照片不会进入请求或数据库，服务端仅保存 `look_json`。目前仓库没有一期的 CLIP 图像分类模型，发型与眼镜使用本地规则估计；判断不准时可在个人中心微调。

个人中心的全身预览和从公告进入的他人主页现在共用 `pixel-3d/` 的可旋转体素形象查看器；各自使用当前用户保存的 `look` 配方。书包颜色由 `packColor` 保存，旧账号缺少该字段时使用默认棕色。查看器可拖动、缩放和切换四个方向，关闭主页时会卸载。

个人中心提供签名、学院、年级、兴趣标签的公开开关，以及眼型、瞳色、裤子、配饰单独染色。兴趣输入后按回车或逗号会成为可移除的标签。自己的公告和已发送私聊记录在个人中心按对象分类，仅本人可查询。点击别人的公告或聊天头像出现“发起对话 / 个人主页”菜单；同场景距离约 52 像素时显示缩略卡和两个入口，缩略卡与主页头像本身不重复弹出菜单。别人的主页按字段排列所有公开资料，未填写的字段会标明。公告由服务端限为 1–200 字、每人 30 秒一条和每天 20 条，发送后需收到确认才清空输入。网络中断后浏览器会持续重试，并在网络恢复时立即尝试恢复联机。

## 四个角色

地图里原有的保安老丁、食堂阿姨、算法哥、学霸姐位置与对话入口保留。靠近角色按 C 时，大厅为当前用户签发对应服务的独立账号票。主地图的独立“玩家精灵”按钮可呼叫老丁，他会沿地图路径赶来；到达后直接在地图上展开对话，走近按 C 也走同一入口。角色服务须在大厅电脑上运行；未运行时地图会提示，地图和聊天仍可使用。一键启动器只启动本机已有依赖，日志在 `mp/runlogs/`；按 Ctrl+C 停止由该次脚本启动的子进程，已运行的服务不会被结束。

| 角色 | 本地服务 | 原项目启动位置 |
| --- | --- | --- |
| 老丁 | `127.0.0.1:8000` | `laoding`；当前 Python 已安装 FastAPI 时直接运行 `python server/app.py`，避免本机随附 `server_vendor` 的二进制依赖与 Python 版本不匹配 |
| 学霸姐 | `127.0.0.1:8010` | `xueba-ge`；优先使用 `.venv`，否则用已安装的 Python 3.13；知识索引仍需先按 `DEPLOY.md` 建好，本地启动设置 `XBG_LOCAL_MODE=1` |
| 食堂阿姨 | `127.0.0.1:8020` | `campus_game_cmr`；`python -m uvicorn aunt.server:app --host 127.0.0.1 --port 8020` |
| 算法哥 | 后端 `127.0.0.1:8081`，前端 `127.0.0.1:3001` | 使用 `mp/mysql-dev` 中已初始化的隔离 MySQL，监听 `127.0.0.1:3307`；从 `mp/mysql-pass` 读取本机数据库密码，源码更新时用本机 Maven 离线构建，再启动原 Java 包和 Vite |

3000 端口只由大厅使用；大厅联机 WebSocket 用 8090。其余服务均只监听 `127.0.0.1`，算法哥前端在 3001，由大厅代理到 `/agent`。启动器不会初始化数据库，也不会使用系统 MySQL 数据目录；若 `mp/mysql-dev` 或密码文件不存在，仅跳过算法哥服务。四个原服务的独立认证接口仍供大厅内部建立角色账号，浏览器里的四套认证页面和按钮已去掉；直接访问角色页面必须先经大厅登录和取票。

## 验证

在项目根目录运行：

```powershell
python mp/test_map.py
node mp/test_look.js
python mp/test_smoke.py
python mp/test_npc_bridge.py
python mp/test_profile_history.py
```

`test_smoke.py` 在一台电脑上模拟三个独立客户端，检查场景隔离、移动、公告、限流、私聊、离线消息、资料和账号顶替。`test_npc_bridge.py` 使用四个本地服务替身，检查两名大厅用户的四套角色账号独立。`test_profile_history.py` 需先按下文方式启动 3012 临时大厅，并把 `DB` 常量指向该临时库；它验证公开资料、隐藏字段和本人发送记录的权限。按本次任务要求，真正的跨电脑验收仍须至少三台电脑在同一局域网登录：分别上传照片、互看移动和形象、公告与私聊互通、离线重连后查消息，并逐一与四个真实角色互动。未做这一步前，不能标记为跨电脑通过。

本机 UI 回归已验证：空白登录页与南门重生、两账号 NPC 历史分离、头像双选菜单、靠近玩家卡片与私聊、公告确认及限流反馈、单机食堂打开并可退出单机、兴趣标签、发送记录、甜品蛋糕问题的资料边界答复、老丁沿路到达后自动在地图展开对话，以及断开再启动本机大厅后浏览器无刷新恢复联机。形象测试使用用户提供的 `5.bmp`，识别到深色马尾、眼镜与黑白横条纹；照片只在浏览器本地处理。跨电脑和多人真实物理设备验收仍待设备。

四个原服务都在本机运行时，可再测真实换票与账号隔离：保持角色服务 `8000/8010/8020/8081`、算法哥 Vite `3001` 和隔离 MySQL `3307` 运行，另用 `MP_DB=mp/agent-test.sqlite3`、`MP_HOST=127.0.0.1`、`MP_HTTP_PORT=3012`、`MP_WS_PORT=8092` 启动临时大厅，在项目根目录执行 `python mp/test_real_agent.py` 和 `python mp/test_real_npcs.py`。脚本会创建随机测试账号，测试完成后停止临时大厅即可删除 `mp/agent-test.sqlite3*`；不要把正式大厅数据库用作这组测试。真实测试已验证两名用户分别取得四家角色票、四个代理页面可载入，且学霸姐、食堂阿姨、算法哥的空会话及历史接口按账号隔离。这组测试只读资料或新建空会话，不发送会调用外部模型的对话请求。老丁只有 `/api/me` 账号接口，聊天历史在浏览器本地按用户 ID 分片，没有服务端历史接口可测。

当前大厅的唯一可见登录入口已接通四个角色，但账号和密码的权威来源仍是 `mp/lobby.sqlite3` 的 `mp_user` 表；算法哥 `8081` 的 `user` 表是按大厅用户建立的角色账号。任务书要求以 `8081` 的 `user` 表作为唯一账号源，这一架构调整尚未完成，不能据此宣称该条已验收。

不搬到服务器。访问范围仅限本机或可信局域网；照片在浏览器本地转换。若要上线公网，需要另行配置 HTTPS、持久会话和运维策略。
