# 学霸哥 · 角色功能与实现

| 项 | 内容 |
|---|---|
| 角色 | 学霸哥（原「学长 · 甲」人格细化，非新角色） |
| 定位 | **课业辅导型智能体** |
| 对标 | 与「算法哥」相对——算法哥管竞赛刷题，学霸哥管课业考试 |
| 版本 | v1.0 · 2026-09-18 |

---

## 一、一句话定位

**校园里那个成绩最好、笔记最全、什么课都能给你讲明白的学长。**

他和算法哥是**一对**：算法哥是「打比赛的」，学霸哥是「卷绩点的」。两个人都懂技术，但走的路完全不同。

---

## 二、功能清单

### 2.1 课本问答（核心）

**他能回答什么**——概念、原理、机制类问题，且答案**从教材里来**：

| 课程 | 典型问题 |
|---|---|
| 操作系统 | 什么是死锁？进程和线程的区别？页面置换算法有哪些？ |
| 计算机网络 | TCP 为什么需要三次握手？拥塞控制怎么做的？ |
| 数据结构 | B+ 树和 B 树的区别？红黑树怎么保持平衡？ |
| 数据库 | 事务的隔离级别？索引为什么用 B+ 树不用哈希？ |
| 编译原理 | 什么是 LR 分析？文法怎么消左递归？ |
| 软件工程 | 敏捷和瀑布的区别？什么是设计模式？ |
| 高数 / 线代 / 概率 | 洛必达什么时候能用？矩阵秩的几何意义？ |

**输出要求**：
- **基于指定教材回答**，不是凭记忆瞎说
- **带出处**——标出《操作系统》第 3 章第 2 节，可点开验证
- **跨教材对比**：同一问题不同教材怎么说
- **能追问**：答完可以接着问"那为什么要这样设计"

### 2.2 解题辅导

**不给现成答案，给思路和步骤。**

| 类型 | 例子 |
|---|---|
| 数学类 | 高数求极限/积分、线代求特征值、概率求分布 |
| 程序类 | 算一段 C 程序的输出、找出代码里的 bug |
| 数据库类 | 算一条 SQL 的查询结果、画 ER 图 |
| 操作系统类 | 算调度算法的周转时间、算页面置换的缺页次数 |
| 网络类 | 算子网划分、算 CRC 校验、算传输时延 |

**输出要求**：
- **一步步来**，每一步都能停下来问
- 卡在第几步，就讲第几步
- **和算法哥一样的设计：不给最终答案，给到达答案的路**

### 2.3 往年资料

- **往年试卷**、**复习提纲**、**讲义**
- 按课程检索：「有没有高数的往年卷」「操作系统的复习提纲」
- 资料形态待定（见 §五）

### 2.4 复习规划

- 「这门课怎么学」——从哪章开始、哪章是重点
- 「考试考什么」——范围、题型、分值分布
- **课程依赖**：「学数据结构前要不要先学离散数学」

### 2.5 校园信息问答（保留，非主打）

原有的 800 条校园信息切片保留，作为兜底能力。**不作为他的主打方向**——他的舞台是课业。

## 三、实现方案

### 3.1 知识库构建（离线做一次）

```
教材（PDF / 扫描件）
  → OCR 出文字
  → 语义切片
  → 每片算向量
  → 每片带出处元数据
  → 入库
```

**切片策略**：
- **按语义边界切**（章节、自然段），不按固定字数硬切
- 切片**适度重叠**，避免答案正好落在切口上
- 每片携带元数据：`课程 / 教材 / 章节 / 页码`

**三类数据源**：
1. 教材（待定几本）
2. 往年资料
3. 校园信息切片（**自备 800 条**——不取用其他角色的数据）

### 3.2 检索层 —— 这是核心

**双路检索 + 融合 + 精排**：

| 路 | 做什么 | 找什么 |
|---|---|---|
| **BM25 倒排索引** | 字面匹配 | 专有词、术语（"三次握手""B+ 树"）——**字面比语义更准** |
| **向量余弦** | 语义匹配 | 换了说法的问法（"进程和线程啥区别"）——**字面匹不上但意思对** |
| **RRF 融合** | 两路结果融合排序 | 取长补短 |
| **Reranker 精排** | 交叉编码器对 top 结果二次精排 | 把最该在前面的顶上来 |

**为什么必须混合**：纯向量会漏掉精确术语，纯关键词答不了换了说法的问法。**两条腿走路，才叫真检索。**

### 3.3 生成层

| 用什么 | 效果 |
|---|---|
| **top-k 片段 + 问题 → LLM** | 根据课本讲，有据可依 |
| **结构化输出** | 回答里带出处，可验证 |
| **流式输出** | 边想边出字 |
| **Prompt caching** | 课本片段作为固定前缀缓存，快且省 |
| **多轮上下文** | 追问时他知道你刚问了什么 |

### 3.4 模型选型与运行

| 用途 | 选型 |
|---|---|
| **Embedding** | bge-m3 / Qwen3-Embedding（中文强、多粒度） |
| **Reranker** | bge-reranker 系列 |
| **生成** | **自带 LLM 接入**——Key 与配置在本交付件内，**不调别人的服务** |
| **运行** | **浏览器内 WebGPU + ONNX 推理**——真推理，不是调接口 |

### 3.5 为什么这么选（答辩用）

**问：为什么不用向量库 / FAISS？**

> 课本总共几千个片段，这个量级下**暴力余弦比查索引还快**，加 HNSW 是负收益。
>
> 我们预留了切换点：**语料超过十万条时换成 HNSW——那是配置项，不是重写。**

**问：为什么混合检索？**

> 教材里的术语（"三次握手""B+ 树"）字面匹配比语义匹配更准；学生的口语提问（"进程和线程啥区别"）语义匹配比字面更准。**单路必漏，双路才全。**

## 四、边界

### 4.1 与算法哥

| | 学霸哥 | 算法哥 |
|---|---|---|
| 主题 | 课业、考试、课本 | 竞赛、刷题 |
| 形态 | 讲原理、给资料、解推导题 | 出题、判题、看代码 |
| **分界** | **要讲原理、要资料、要一步步推导的找他** | **能提交代码判分的找他** |

**重叠区处理**：数据结构大作业这种既是课业又是算法的——
- **交代码判分的部分 → 算法哥**
- **写报告、讲原理的部分 → 学霸哥**

### 4.2 与其他角色

| 角色 | 分工 |
|---|---|
| 向导 · 小北 | 他管**空间**（在哪、怎么去），学霸哥管**知识**（为什么、怎么办） |
| 阿姨 · 丙 | 阿姨管**吃**，学霸哥管**学** |
| 保安 · 老丁 | 无重叠 |

### 4.3 与其他角色的记忆隔离

**学霸哥记得你问过什么，但其他角色不知道。** MVP 阶段角色之间零交流——这是为下一步的「信息走样」留的空间。

## 六、独立交付与合体接口

**本角色按隔离开发：知识库与实现自包含，可独立开发、独立演示。**

### 6.1 交付件形态

**一个能独立跑起来的小应用**——登录进去，问课本问题，拿到带出处的回答。

```
学霸哥/
├── index.html          登录窗口 + 聊天界面（单页）
├── app/                切片 / 混合检索 / 生成
├── data/               知识库（切片 + BM25 索引 + 向量）
└── server/             账号服务
    └── main.py         FastAPI：注册 / 登录 / 签发 token
```

**怎么跑**：

```bash
pip install fastapi uvicorn
uvicorn server.main:app --port 8000
# 再打开 index.html
```

**答辩时怎么演**（一句话动线）：

> 打开页面 → 登录 → 问「三次握手为什么要三次」→ **答案带出处，点开能回到课本那一页**。

**账号服务**：**轻后端**（FastAPI + SQLite）——注册 / 登录 / 签发 token。
**它不是登录 UI 的附属，是「记忆归属」的前提**：有了 `user_id`，记忆才能跨会话、跨设备挂在**同一个人**身上。
**本交付件自带一套，独立可跑**；合体时五套并成一套统一账号。

### 6.2 合体接口

| 项 | 内容 |
|---|---|
| **自包含** | 知识库、切片、检索层、生成层——**全部在本角色内闭环**，不依赖其他角色的实现 |
| **唯一的外部约定** | 教材 / 课件的**电子版来源**——**是素材约定，不是实现依赖** |
| **合体方式** | 按总体设计 §2.2 的「工具集 + 人格配置」接入，对外暴露 `askTextbook()` / `explainProblem()` / `makeStudyPlan()` |
| **合体后** | 引擎读 `tools` 知道他会干什么、读 `persona` 知道他怎么说话——**引擎一行不改** |

> **本文档改过一次口径**：原 §六 名为「这套技术的复用价值」，列了"阿姨复用检索、保安复用检索、算法哥复用检索"。
> 那与隔离开发的组织事实冲突——**每份角色文档是独立交付物，不该把别人写成自己的下游**。整节已重写。
>
> **工具名冲突提醒**：复习规划原拟 `makePlan()`，与算法哥的题单生成器同名，
> 本文档取 **`makeStudyPlan()`** 避开；若保留重名，需靠**角色命名空间**隔离。
