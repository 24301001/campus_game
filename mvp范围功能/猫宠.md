# 猫宠 · 第一阶段实现计划（程序化猫谱）

| 项 | 内容 |
|---|---|
| 玩法出处 | 总体设计 **§22.7 校园猫谱** |
| 阶段 | **第一阶段：零 LLM，纯程序化**（已拍板） |
| 定位 | `type: "cat"` —— **与五个角色同构的智能体**，表达方式是**动作**不是语言 |
| 规模 | **4 只猫**（§22.7 给的是 3~5 只） |
| 状态 | ✅ 不用 LLM ／ ✅ 无猫粮货币、无物品栏（§22.7 已排除） |
| 版本 | v1.0 · 2026-09-19 |

---

## 一、第一阶段做什么

**把 4 只猫做成会按领地活动、按好感档位反应的智能体——全部查表，一次 LLM 调用都不用。**

三句话说完：

| # | 判断 |
|---|---|
| 1 | **猫是智能体**——`roam`（领地）+ `schedule`（作息）+ 记忆 + 行为表达，**四个要件一个不缺** |
| 2 | 但它的表达方式是**动作**，不是说话 ⇒ **不需要 LLM** |
| 3 | 行为判定 = **查表 + 算距离** ⇒ **每帧跑也不心疼** |

## 二、完整功能（§22.7 原文口径）

### 2.1 好感度不是进度条，是一套行为

| 档 | 它怎么对你 |
|---|---|
| **陌生** | 远远看见你就跑 |
| **眼熟** | 不跑，但你走近它退 |
| **熟** | 让你靠近，**但不让摸** |
| **亲近** | **让你摸**，在你脚边蹭 |
| **很亲** | **主动走向你**，跟你走一段路 |
| **最亲** | 在你常出现的地方**等你**（罕见） |

### 2.2 掉档规则

- **不喂就往下掉档**，但**是渐进的，不是断崖**——玩家不是突然发现"猫没了"，而是察觉到"**它最近不太理我了**"
- **衰减以「周」为单位，不是「天」**（以天为单位就变成每日任务了）
- **猫不会饿死，只会疏远**——**可以重新建立**
- 掉到「熟」= 它不再主动靠近你；掉到「眼熟」= 你想摸它会走开

### 2.3 各自独立 + 图鉴

- 这只跟你熟，**不代表那只跟你熟**——一只一只来
- **认识一只，图鉴点亮一格**（共用 §22.5 那张图鉴，不多做 UI）

### 2.4 它会过日子（读 §9 时间层）

早上在食堂后门等早饭、中午窝着睡、下午去草坪、**夜里回自己的窝待着**。
（⚠️ **全天都在**——不吃"晚上消失"那套，见 §4.2 那条口径。）

### 2.5 交付规模

| 项 | 量 |
|---|---|
| 新美术 | **3~5 只猫的毛色花纹差异**——**本玩法是唯一需要新美术的**（精灵走地图的人物绘制系统） |
| 新引擎 | **零**——领地是 `roam` 的另一种配置 |

## 三、为什么第一阶段不用 LLM（拍板记录）

六档本身是**一张确定的映射表**，不是推理。把它交给 LLM 要付三个代价：

| 代价 | 具体 |
|---|---|
| **慢** | 猫的行为是**实时表现**——它跑不跑，不能等一次推理 |
| **不稳** | 同一档位，今天让摸明天不让摸——**"它认识我"被搞成了随机** |
| **贵** | 每只猫每次交互一次调用，4 只 × 每个玩家 |

第三条最要命：

> **§22.7 的立身之本是「行为就是呈现」。**
> 而 LLM 天生**会漂**——一个会漂的东西，**呈现不出"它记得你"**。

**同一条原则**（与五个角色一致）：**该确定的地方用确定性。**
向导那边是"空间事实不交给 LLM"，这里是"**好感度判定不交给 LLM**"。

> **LLM 的位置留着，但第一阶段不用。** 触发条件是**猫开始说话**（比如摸到时冒一句心情）——
> 那时也该是**稀有触发**，不是每帧调。

## 四、猫 = 智能体：配置结构

### 4.1 与五个角色同构

§2.2 的公式 `功能 = 智能体 = 工具集 + 人格配置`，猫一条不缺：

| 智能体要件 | 猫的对应物 |
|---|---|
| `roam` | **领地** |
| `schedule` | **作息**（读时间层） |
| 记忆 | **每只猫单独记得你** |
| 人格 | **脾气**（有的亲人、有的怕生） |
| 表达 | **六档行为** |

**差别只在 JSON**——引擎一行不改。

### 4.2 猫的配置

```json
{
  "id": "cat_daju",
  "name": "大橘",
  "type": "cat",
  "home": "canteen_back",

  "roam": { "type": "territory", "speed": 8, "radius": 90 },

  "schedule": [
    { "at": "canteen_back", "from": "06:00", "to": "11:00" },
    { "at": "canteen_back", "from": "11:00", "to": "14:00" },
    { "at": "grass_sys",    "from": "14:00", "to": "18:00" },
    { "at": "canteen_back", "from": "18:00", "to": "06:00" }
  ],

  "temperament": { "warmup": "fast" },

  "reactions": {
    "陌生": { "dist": 120, "act": "flee" },
    "眼熟": { "dist": 60,  "act": "retreat" },
    "熟":   { "dist": 30,  "act": "idle" },
    "亲近": { "act": "allow_touch" },
    "很亲": { "act": "approach_follow", "sense": 200 },
    "最亲": { "act": "wait_at_habitual_place" }
  }
}
```

> ⚠️ **猫全天都在，`at: null` 不用**（2026-10-09 用户拍板）。
> 用户原话：「猫应该一整天都在哈，这不需要设计晚上消失的逻辑」。
> 原来的作息表每张最后一段都是 `{ "at": null, ... }` ⇒ 一天里有 12~13 小时
> **校园里一只猫都没有**，晚上打开地图会以为猫没做出来 —— 这条**已废**。
> 现在的口径：**每只猫 24 小时都待在某个点上**，作息只负责"**一天里换地方**"
> （大橘白天在食堂后门、下午去草坪、夜里回食堂后门）。夜里不另加逻辑，
> 猫在窝里照常待机/游走，玩家照样能蹲下喂它。
> 冻结的《概要设计说明书》本来就只说"每只猫有独立领地与作息"、"校园在不同时刻
> 呈现不同状态"，**没有**"晚上不出现"这条，所以这次改动不碰那份文档。

### 4.3 四只猫

| 猫 | 毛色 | 领地 | 脾气 | 演示上负责什么 |
|---|---|---|---|---|
| **大橘** | 橘猫 | 食堂后门 | 亲人（`fast`） | **最快能摸到**——演示"好感是攒出来的" |
| **馆长** | 三花 | 图书馆台阶 | 怕生（`slow`） | **最难**——演示"同一只猫，别人摸不到你能摸" |
| **芝麻** | 黑猫 | 明湖南岸影壁 | 谨慎 | 中间档 |
| **狸花** | 狸花猫 | 思源楼草坪 | 中间 | 中间档 |

> 老体育馆那 13 级台阶**第一阶段不做**（§22.7 列的第五个点位，留作扩充）。

## 五、行为判定：查表 + 距离

### 5.1 判定流程

```js
// 每帧，对每只猫
const memo  = affinityOf(playerId, cat.id);        // 一条记忆记录（见 §六）
const score = effectiveScore(memo, now);           // 惰性衰减后的有效值
const tier  = tierOf(score);                       // 0-100 → 六档
const rule  = cat.reactions[tier];                 // 查表

if (dist(player, cat) < rule.dist) {
  play(cat, rule.act);                             // 触发动作
}
```

**纯计算。没有网络、没有模型、没有随机数。**

### 5.2 档位 → 数值

| 档 | 分数区间 | 触发距离 |
|---|---|---|
| 陌生 | 0–19 | 120px 内跑 |
| 眼熟 | 20–39 | 60px 内退 |
| 熟 | 40–59 | 可走到 30px，按摸 → 退 |
| 亲近 | 60–79 | 30px 内可摸 |
| 很亲 | 80–94 | 200px 内主动靠近并跟随 |
| **最亲** | **95–100** | 在你常出现的地方等你 |

> **「最亲」罕见**是设计目标，不是巧合——门槛故意拉高，且要求**长周期不掉档**。

## 六、好感度怎么存（**关键决策**）

### 6.1 设计文档已经给了答案

> §22.7：**零新引擎——好感度就是记忆系统里的一条记录。**

所以不新建表、不新建系统。用 §3.1 已有的记忆条目结构：

```
{ desc, time, importance, visibility, playerId, source }
```

### 6.2 一条记录怎么当"水位"用

**关键区别：猫的记忆是 `upsert` 一条，不是 `append` 多条。**

| | 普通记忆 | 猫的好感记忆 |
|---|---|---|
| 写法 | 每到一件事 **append** 一条 | **每对（玩家 × 猫）只有一条**，反复 **upsert** |
| `importance` | 这件事多重要 | **当前好感度**（0–100） |
| `time` | 这件事什么时候发生 | **最后一次喂的时间** |
| `desc` | 事情本身 | 固定串（仅供调试） |
| `source` | 来源 | **`"cat_affinity"`**（唯一标识这类记录） |

**一条记录，两个字段，两件事都办了。** 零新引擎直接成立。

- 检索键：`(playerId, catId, source="cat_affinity")`
- **不是 append ⇒ 查询成本不随历史增长**，永远 O(1)

### 6.3 惰性衰减：不跑定时任务

```
effectiveScore(memo, now):
    weeks = floor((now - memo.time) / 7天)
    return max(memo.importance - weeks * 衰减步长, 0)
```

**读的时候才算，不回写。** 好处：

| 好处 | 说明 |
|---|---|
| **不用定时任务** | 没有"每小时扫全表扣分"这种东西 |
| **离线也对** | 玩家一周没上线，回来读一次就是对的 |
| **各猫独立** | 每只猫自己一条 `time`，互不影响 |

### 6.4 一条实现铁律：**先结清，再累加**

喂食时**必须先算衰减再累加**，否则会"把上个月的旧分带到今天":

```js
const cur = effectiveScore(memo, now);   // ① 先把衰减结清
memo.importance = cur + Δ;               // ② 再累加这次喂的
memo.time       = now;                   // ③ 时间戳推到当前
```

**顺序写反就是 bug**（玩家隔一个月回来喂一次，分数会虚高）。

### 6.5 不给玩家看数字

> §22.7：**不给玩家看好感度数字，行为就是呈现。**

- UI 上**没有任何进度条、没有任何数字**
- 玩家只能从**猫的反应**推断——"它今天让我摸了"
- **图鉴只记录"认识了"**，不记录"多熟"

## 七、「喂」怎么触发（**关键决策**）

### 7.1 设计文档把这条留给我们

> §22.7：**"喂"具体怎么触发（要不要食物、食物从哪来）留给你们定**；
> 但**不做猫粮货币和物品栏**——那会把系统复杂化，也破坏"不点菜单"。

### 7.2 方案：**走近 + 就地动作轮盘**

> 2026-10-09 用户改成轮盘，原话：「我建议我们点击一下 g 显示一个轮盘，上面有我们可以
> 对猫的几个动作，点击对应扇区执行对应动作」。轮盘四格由用户拍板：
> **摸 / 喂 / 叫它 / 逗它**（**不要拍照**）。

| 步 | 动作 |
|---|---|
| 1 | 玩家走到猫旁边（**`CAT_REACH_R` = 120px** 以内，见下） |
| 2 | 按 **`G`** 弹出**就地动作轮盘**（四格：摸 / 喂 / 叫它 / 逗它） |
| 3 | 点某一格 → 执行该动作（摸/喂时**玩家自己蹲下**，猫**走过来**） |
| 4 | 喂食进入**冷却**——同一只猫**每天一次**（按真实日期，§9 时间层） |

**"不点菜单"保住了**（原样保留）：轮盘是**就地弹的动作盘**，
**不开背包、不选道具、不翻页**；而且**盘里只有动作**——
没有道具、没有数量、没有好感数字（§6.5 那条不松）。

**两个半径不是一回事，别混**：

| 常量 | 值 | 是什么 |
|---|---|---|
| `CAT_TOUCH_R` | 30px | **猫的忍受带**——猫允许你靠到多近还不跑（§5.2，由档位决定） |
| `CAT_REACH_R` | 120px | **玩家能开口的距离**——站这么近才按得出轮盘。远了你连盘都开不了，"叫它"就没有意义 |

> ⚠️ `CAT_REACH_R` 是第四十四轮新加的常量。不能拿 `CAT_TOUCH_R` 当开轮盘的门槛：
> 那对"亲近"档只有 30px，等于**猫和人必须贴脸才能互动**，
> 而"猫从那儿走过来蹭你"的表演需要**一段距离**才看得出位移。

### 7.3 为什么不做食物 / 物品栏 / 猫粮货币

| 不做 | 理由 |
|---|---|
| **物品栏** | §22.7 已排除；而且会牵出"食物从哪来、怎么存、怎么显示"一整套 UI |
| **猫粮货币** | §22.7 已排除；货币会把这个玩法变成"任务—奖励"闭环，**破坏"逗猫"的性质** |
| **不同食物不同效果** | 直接把系统复杂化，第一阶段收益为零 |

**"喂"就是喂**——不带经济系统。

> ⚠️ **猫粮是一次性表现，不是物品**（第四十四轮补）。
> 用户要的"蹲下来放猫粮"是这么落地的：**蹲下 → 地上出现一小堆 → 猫走过来低头吃掉
> → 到点消失**。全程**不进背包、不计数、不消耗库存、不做商店**。
> 它只是渲染帧里的一个世界物体（`CAT_FOOD`），连碰撞盒都没有。
> 上面三条排除**一条没松**。

### 7.4 冷却为什么是"每天一次"

- **防止刷**：站在猫跟前点二十下就"最亲"，六档就白设计了
- **对齐衰减单位**：衰减按**周**，涨分按**天** ⇒ **每周喂 1~2 次就能维持**，符合"养一只猫"的真实节奏
- **和 §22.9「不做每日任务」不冲突**：这里是**上限**不是**配额**——不喂没有惩罚，只有疏远

## 七·五、动作规格（猫 + 人）

> 本节补 §22.7 与 §八 没写清的部分：**猫的十个动作**与**人的两个动作**的具体规格。
> 口径：猫的四向都要画——六档行为全是相对玩家的方向，**"面向你退"与"背向你跑"必须能读出区别**。
> 第四十四轮加了 `look` / `play` 两个（"叫它"和"逗它"要有得演），八个 → **十个**。

### 7.5.1 猫的十个动作

| # | 动作 | 触发 | 帧 | 朝向读法 |
|---|---|---|---|---|
| 1 | `walk` 游走 | `roam.type:"territory"` 领地内 | 4 | 行进方向 |
| 2 | `idle` 待机 | 默认 | 2 | 呼吸 + 尾巴摆 |
| 3 | `sleep` 睡 | 作息时段（中午） | 2 | 团成一团，耳朵不动 |
| 4 | `flee` 跑 | 陌生（120px 内） | 4 | **背向**玩家 |
| 5 | `retreat` 退 | 眼熟（60px 内） | 2 | **面向**玩家倒退 |
| 6 | `rub` 蹭 | 亲近（可摸） | 2 | 绕玩家脚边 |
| 7 | `wait` 等 | 最亲（罕见） | 2 | 蹲坐在你常出现处 |
| 8 | `eat` 吃 | 喂食反馈 | 3 | 低头吃食 |
| 9 | `look` 抬头 | 叫它 / 逗它（生档） | 2 | 头抬高 1px + 耳前倾，正对着你 |
| 10 | `play` 扑 | 逗它（亲近及以上） | 4 | 低伏 → 前扑 → 侧翻 → 起身 |

**「跟」（很亲档的 `approach_follow`）不新画**——复用 `walk` 的帧，只是速度与时间预算不同。

**四向**：`down` / `up` / `right`；**`left` 由 `right` 镜像**得到（与地图现有角色同规）。

### 7.5.2 人的两个动作

§7.2 的"走近 + 一个动作按钮"要求玩家有**实体动作**——否则"撸猫"只是猫在演独角戏。
新增两个姿态（**下蹲共用躯干，只换手臂**）：

| # | 动作 | 帧 | 用在哪 |
|---|---|---|---|
| 1 | **蹲下摸** | 2（伸手前 / 手到） | 亲近档撸猫 |
| 2 | **伸手喂** | 2 | 喂食交互 |

- **四向都出**（正对 / 背对 / 左 / 右）：蹲下时玩家可能朝任意方向，
  只画两向会在朝上或朝下时露馅。
- 其余时候玩家仍是现有的 走 / 待机，**不新增**。
- ⚠️ 下蹲是**另一套纵向预算**——站立式的"头-躯干-腿"三段平分撑不住蹲姿
  （腿是折的、髋是压低的），必须单独算一套行高。**共用躯干、只换手臂**：
  `pet` 手伸向前下方，`feed` 的手再低 1px（＝把粮放到地上）。
- ⚠️ 画布与锚点**必须和站姿逐字相同**（`CH_W=18, CH_H=30, CH_AX=9, CH_AY=27`），
  否则人一蹲就"跳"一下。
- ⚠️ 翻转约定照**人物**（**只有 `right` 翻转**），**不是**照猫的（猫是 `left` 翻转）。
  照猫的写法抄 = 人左右镜像。

### 7.5.3 精灵预算

| 对象 | 算法 | 张数 |
|---|---|---|
| 猫（每动作烘焙 3 向，`left` 镜像） | `(4+2+2+4+2+2+2+3+2+4)` 帧 × 3 向 | **81 / 猫** |
| 四只（毛色走配色参数，一套代码换四色） | 81 × 4 | **≈ 324** |
| 人（蹲下摸 2 帧 + 伸手喂 2 帧，各 4 向） | 2 × 2 × 4 帧 | **16** |

> 十个动作是 `CAT_ACTS` 那张表的键：`walk/idle/sleep/flee/retreat/rub/wait/eat/look/play`。
> 帧数按需烘焙（`poseSprite` 做缓存），不是启动时全画 —— 四只猫 × 81 张全预烘太浪费。

### 7.5.4 动作与档位的对应（收口 §5.2）

| 档 | 分数 | 触发距离 | 动作 |
|---|---|---|---|
| 陌生 | 0–19 | 120px | `flee` |
| 眼熟 | 20–39 | 60px | `retreat` |
| 熟 | 40–59 | 可至 30px | `idle`（按摸则 `retreat`） |
| 亲近 | 60–79 | 30px | `rub` |
| 很亲 | 80–94 | 200px | `walk`（复用，作"跟"） |
| 最亲 | 95–100 | 常去处 | `wait` |

**玩家主动动作 → 猫的反应**（第四十四轮补，轮盘四格）：

| 动作 | 陌生 | 眼熟 | 熟 | 亲近 | 很亲 | 最亲 |
|---|---|---|---|---|---|---|
| **摸** | 退开 | 退开 | 退开 | **走过来蹭腿**（`rub`） | 同左 | 同左 |
| **喂** | **肯过来吃** | 肯 | 肯 | 肯 | 肯 | 肯 |
| **叫它** | `look` 抬头 | `look` | `look` | `look` + 走近两步 | 同左 | 同左 |
| **逗它** | `look` | `look` | `play` 扑 | `play` 扑 | `play` 扑 | `play` 扑 |

> ⚠️ **喂食任何档位都肯过来**——这是**必须的**，不是宽松：§10 里喂是唯一的涨分途径，
> 在这里加一条"生猫不吃"，等于把「陌生 → 亲近」的梯子从底下锯断（构建期有一条断言盯着）。
> 同理，**喂食期间 `comeTo` 优先于六档行为** ⇒ 陌生猫不会一边被你喂一边 `flee`。

## 九、验收（做到什么算完）

| # | 验什么 | 通过标准 |
|---|---|---|
| 1 | **六档齐全** | 手动把分数拨到六档，**猫的行为逐档正确**（跑 / 退 / 不躲不让摸 / 让摸蹭 / 主动跟 / 老地方等） |
| 2 | **攒得上去** | 连续喂，从「陌生」到「亲近」，**中间必须经过"不让摸"的「熟」档**——**跳档就算错** |
| 3 | **掉得下去** | 改 `time` 往前拨两周 → 档位下降 → **行为肉眼可见地变了**；**不消失、不归零** |
| 4 | **各自独立** | 把大橘喂到「亲近」，**馆长仍然是「陌生」**——见你就跑 |
| 5 | **作息切换** | 拨到 20:00 → 四只猫**都在**（各自回自己的窝）；拨到 09:00 → **大橘在食堂后门**、狸花在草坪。⚠️ **任何钟点都不许出现"一只猫都找不到"**（2026-10-09 用户否掉了原来"晚上不出现"那条） |
| 6 | **边界安全** | 站原地连点喂食 **20 次**，**只算一次**（冷却生效） |
| 7 | **不出圈** | 长时间观察，**猫始终在 `radius` 内**，不走进楼里、不穿墙 |
| 8 | **图鉴点亮** | 四只猫遇到一只点亮一格，**四格互不覆盖** |
| 9 | **零调用** | 断网 / 拔掉 LLM Key，**以上八条全部照常**——这就是"程序化"的定义 |
