# 向导 · 角色功能与实现

| 项 | 内容 |
|---|---|
| 角色 | 向导 · 小北（校园志愿者） |
| 定位 | **空间理解与带路型智能体** |
| 对标 | 与前四个都不同——**他是地图的理解层** |
| 底座 | **完整的校园地图**（现成资产）＋ 校园图谱 |
| 版本 | v1.0 · 2026-09-19 |

---

## 一、一句话定位

**校园里那个什么都知道在哪、也说得清怎么去的志愿者。**

他最特别的地方有两个：

**① 只有他回答问题时会带你过去。**
其他角色都是用文字回答，**只有他能把镜头飞过去、把路高亮出来**。

**② 他懂的不只是"在哪"。**

> 玩家问"**我想找个安静的地方自习**"——这句话里根本没有地名，
> 但小北答得上。**这就是"对地图有理解"和"查地图"的区别。**

**全文的题眼：LLM 不懂空间。**
所以空间事实**一律不交给它**——它只干两件它擅长的事：**听懂人话**、**说人话**。

## 二、功能清单

### 2.1 问路与带路（核心）

**"二食堂怎么走"**——最常问的一句。

| 步 | 动作 |
|---|---|
| 1 | 解析起点与终点（起点默认"你现在站的地方"） |
| 2 | `findPath()` 取可行走路径 |
| 3 | **转述成人话**——见 §3.5 |
| 4 | **镜头飞过去 + 路径高亮** |

**输出要求**：

- **不能只给一条线**——要**说出沿途经过什么**（"过了图书馆右手边那栋"）
- **不能只给坐标**——`findPath()` 的结果**必须转述**，否则他就是个语音播报器
- **问"怎么走"要能答"其实很近，走过去两分钟"**——**距离感比路径本身更有用**

### 2.2 定位与辨认

| 问什么 | 答什么 |
|---|---|
| "我在哪" | 最近的地点 + 朝向 |
| "这是哪栋楼" | 地点识别 + 一句介绍 |
| "南门在哪边" | 方位 + 镜头指过去 |

**输出要求**：**先给最近的已知地点**（"你在三教北侧"），**再给方向**——人认路靠地标，不靠坐标。

### 2.3 找地方（**"理解地图"的直接体现**）

**问句里没有地名，只有需求。**

| 玩家问 | 小北怎么答 |
|---|---|
| "哪有打印店" | **属性检索**：`type=打印店` 的全部点位，按距离排序 |
| "哪能安静自习" | **多属性加权**：`有自习` + `安静` + `现在开着` → 排序 |
| "哪能买水" | 属性检索 + **去重**（便利店和超市都卖水，别列两遍） |
| "哪能办卡" | 属性检索 → 命中不了就**说不知道**，不编 |

**关键**：这一节的答案**全部来自图谱的属性位**，LLM 只负责**把"安静自习"翻译成属性查询**。

> **"安静"不是图谱里的字段，是玩家的词。**
> LLM 把它映射到 `安静: 高` 这个属性上——**这是它该干的活**。
> 至于"三教到底安不安静"，**那是图谱记的，不是它猜的**。

### 2.4 空间关系（**两跳 BFS 的用武之地**）

| 玩家问 | 走什么 |
|---|---|
| "三教旁边有什么" | 两跳 BFS → 邻居列表 |
| "从南门到图书馆路过什么" | `findPath()` 的**途经点** → 抽地标 |
| "哪栋楼离操场最近" | 图上距离排序 |
| "图书馆和学二哪个远" | 两个距离一比 |

**输出要求**：**列地标名，不列坐标**；**按远近排**，不按拼音排。

### 2.5 导览

**"带我看一圈"**——把 `focus()` 串起来，按一条线依次飞过去，每一处配一句话。

**这一节是"锦上添花"，不是刚需**——但它是**答辩时最好演的一块**（镜头一路飞过去，评委会看）。

**该砍什么**：不做语音、不做虚拟导游小动画、不做用户自定义路线。**串三个点到头**，多了没人看得完。

### 2.6 不归他管的

| 问什么 | 推给谁 |
|---|---|
| "图书馆几点开" | **学长 · 甲**——时间归他，不归地图 |
| "二食堂好吃吗" | **阿姨 · 丙** |
| "我丢的卡找到了吗" | **保安 · 老丁** |
| "三次握手是什么" | **学霸哥** |

## 三、实现方案

### 3.1 数据：校园图谱（地点 + 关系 + 属性）

**本文档的全部空间事实来自这一份图谱**——不来自 LLM，不来自地图的渲染层。

```json
{
  "places": [
    {
      "id": "teach3",
      "name": "第三教学楼",
      "alias": ["三教", "3教", "三号楼", "教三"],
      "type": "教学楼",
      "xy": [120, 88],
      "attrs": { "有自习": true, "安静": "高", "插座": "多" }
    }
  ],
  "edges": [
    { "from": "teach3", "to": "library",  "rel": "相邻", "dist": 180 },
    { "from": "teach3", "to": "gate_s",   "rel": "主路", "dist": 620 }
  ]
}
```

| 部分 | 记什么 | 谁用 |
|---|---|---|
| **地点** `places` | 名字 / **别称** / 类型 / 坐标 / **属性位** | 定位、找地方 |
| **关系** `edges` | 谁挨着谁 / 哪条路通 / 多远 | 空间关系、路径转述 |

**三条设计**：

| 设计 | 为什么 |
|---|---|
| **属性位是自由键值**（`安静: 高`） | 玩家的需求五花八门，**字段写死就答不了"哪能安静自习"** |
| **只记"正确"的事实** | 图谱管正确（设计文档 §16），**磨损是记忆的事，不是图谱的事** |
| **两跳以内** | 见 §3.3 |

> ⚠️ **图谱里的 `hours`（开放时间）由学长 · 甲使用，小北不碰**——
> 那是 §11.6 待补的属性位，属时间域，不属空间域（见 §4.1）。

### 3.2 别称解析：**词典优先，不做通用分词**

**这是本文档最难的一块。**

玩家说的**永远不是地图上的正式名**：

| 玩家说 | 地图上叫 |
|---|---|
| 三教、3 教、教三 | 第三教学楼 |
| 学二、二食堂 | 第二学生食堂 |
| 地下 | 学一地下超市 |
| 红房子 | 科学会堂 |

**为什么不能用通用分词器**

> 通用分词器按**统计规律**切词，它没见过"三教"——
> **会把"三教"切成"三 / 教"**，切完就再也对不上地图了。
>
> **专有名词天生反通用分词器**——它越通用，越不认识我们的词。

**做法：词典优先，最长匹配**

```
玩家输入
  → 先拿别称词典做最长匹配（"三教北楼" 优先于 "三教"）
  → 命中的部分【整块取出】，不参与分词
  → 未命中的部分才交给通用分词
  → 两段结果拼起来
```

**关键在"命中的部分整块取出"**——**只要别称词典命中，就绝不让分词器碰它**。

| 要点 | 做法 |
|---|---|
| 词典内容 | 正式名 + 全部别称 + **常见错别字**（"三号教学楼"） |
| 匹配 | **最长优先**——"三教北楼"和"三教"同时命中时取长的 |
| 维护 | **人工整理**，量不大（校内地点几十个 × 每个两三个叫法） |
| 扩充 | 玩家用了词典里没有的叫法 → **记下来，人工确认后入典** |

### 3.3 空间推理：两跳 BFS

**"三教旁边有什么" = 从 `teach3` 出发，沿边走出去两跳，收集节点。**

| 跳数 | 含义 | 问题 |
|---|---|---|
| **一跳** | 紧邻 | 太少——"旁边"往往不止一栋楼 |
| **两跳** | 这一片 | ✅ **正合适** |
| **三跳** | 半个校园 | 太多——问"旁边"却答出了校门口 |

**为什么不是"半径 N 米"**：因为**路不通的近不算近**。

> 隔着一条铁路的两栋楼，直线 50 米，走过去要绕一公里。
> **按图的跳数走，才是人真实的感受。**

**输出排序**：按**图上距离**升序，不按坐标直线距离。

### 3.4 意图路由：六类

**小北的第一步永远是判断"这是在问什么"。**

| 意图 | 例子 | 走哪条路 |
|---|---|---|
| **问路** | "二食堂怎么走" | `findPath()` + 转述 |
| **定位** | "我在哪" | `getPlace()` |
| **找地方** | "哪有打印店" | 属性检索（§2.3） |
| **空间关系** | "三教旁边有什么" | 两跳 BFS（§3.3） |
| **导览** | "带我看一圈" | `focus()` 串联 |
| **不是他的事** | "图书馆几点开" | 推走 |

**分不清时怎么办**：**按最保守的那条走**——宁可问一句"你是想找地方还是想问怎么走"，**不可猜错带错路**。

### 3.5 路径转述：**坐标 → 人话**

**`findPath()` 返回的是一串坐标点。不转述，他就只是个 API 的语音播报器。**

```
坐标点串
  → 抽【关键节点】：起点、终点、拐点、途经的已知地点
  → 关键节点序列 + 玩家所在位置 → LLM
  → "从这儿一直往南走，过了图书馆右手边那栋就是"
```

**一条铁律**：

> **地标序列是图谱给的，LLM 只负责把它串成话。**
> **不许 LLM 自己加地标**——它一旦自由发挥，就会说出"路过体育馆"这种
> **路上根本没有的东西**。

| 转述要点 | 做法 |
|---|---|
| 用**地标**不用距离 | "过了图书馆右拐" > "直行 180 米后右转" |
| 给**距离感** | "走过去两三分钟"——**人关心的是远不远** |
| 起点用**玩家当前位置** | "从你现在站的地方" |
| 不确定就**说大概** | "大概在那一带"——**不硬编精确数字** |

### 3.6 技术栈与运行

**① 图谱层**

| 用途 | 选型 | 理由 |
|---|---|---|
| 空间数据 | **`graph.json`**（地点 + 关系 + 属性） | 几十个地点、上百条边——**这个量级 JSON 直查比数据库快** |
| 别称词典 | **`alias.json`** | 人工整理，量小 |
| 地图 | **完整的校园地图**（现成资产） | 他的一切表现都落在这张图上 |

**② 检索与推理层**

| 用途 | 选型 | 理由 |
|---|---|---|
| 别称解析 | **词典最长匹配 + 未命中部分才分词** | 通用分词器**天生不认识专有词**（§3.2） |
| 空间关系 | **两跳 BFS** | 一跳太少、三跳太多；**按图走才符合真实感受** |
| 属性检索 | 图谱属性位直查 + 加权排序 | "安静自习" = 多属性命中 |

**③ LLM 层**

| 用途 | 选型 | 理由 |
|---|---|---|
| 意图理解 | **自带 LLM 接入**（Key 与配置在本交付件内） | 把"哪能安静自习"映射成属性查询 |
| 路径转述 | 同一个 LLM，**Prompt 里锁死"不许加地标"** | 坐标 → 人话 |
| **不做什么** | **不问它任何空间事实** | **它不懂空间**（§3.8 第一问） |

**④ 地图接口**

| 用途 | 接口 |
|---|---|
| 镜头 | `focus(placeId)` / `highlight([...])` |
| 路径 | `findPath(from, to)` / `nearestWalkable(x, y)` |
| 查询 | `getPlace(id)` / `listPlaces()` |

**⑤ 运行形态**

| 项 | 内容 |
|---|---|
| 载体 | **自带完整校园地图**——他是五个人里唯一带地图的交付件 |
| 出现 | 常驻（设计文档 §13.3） |
| **主动性** | **不做主动搭话**——他在等你问（§3.7） |

### 3.7 与校园的挂接

> **本节写的全是「合体之后怎么接」**——隔离期这些都不存在，**我一个人也能跑**。

| 挂接点 | 内容 |
|---|---|
| **镜头与图层** | `focus()` / `highlight()`——**这是他的主表现手段** |
| **路径高亮** | 把 `findPath()` 的结果画在地图上 |
| **地图** | **自带**（不是接别人的） |
| **主动性** | **不参与**——地图的出口不该主动拦人（见下） |

> **为什么不做主动性**：其他角色在饭点、在路过时会主动搭话，那是**人的行为**。
> 小北是**地图的出口**——他一主动，玩家会觉得**地图在弹窗**。
> **他不主动，是这个角色设计的一部分。**

### 3.8 为什么这么选（答辩用）

**问：为什么不能直接问 LLM 路？**

> **因为 LLM 不懂空间。**
> 你问它"三教在图书馆哪边"，它会**煞有介事地编一个**——而且编得很像真的。
> 所以本文档从头到尾一条线：**空间事实全部来自图谱，LLM 只做"听懂人话"和"说人话"。**

**问：中文分词为什么不能用现成的？**

> **专有名词天生反通用分词器。**
> 它按统计规律切词，没见过"三教"，**会切成"三 / 教"**，切完就再也对不上地图了。
> 我们的做法是**词典优先、最长匹配**——**只要词典命中，就绝不让分词器碰它**。

**问：为什么是两跳，不是三跳？**

> 一跳只有紧邻，**"旁边"往往不止一栋楼**；三跳散到半个校园，**问"旁边"却答出校门口**。
> **两跳正好是"这一片"**——也正好是人说"旁边"时脑子里的范围。

**问：为什么按图的跳数，不按直线距离？**

> **路不通的近不算近。**隔着一条铁路的两栋楼，直线 50 米，走过去要绕一公里。
> **按图走，才符合人真实的感受。**

**问：为什么属性位是自由键值，不写死字段？**

> 玩家的需求**五花八门**——"安静"、"有插座"、"能坐"、"下雨不淋"。
> 字段一旦写死，**就只能答写死的那几个问题**。
> 自由键值 + LLM 做映射，**新需求不用改代码**。

**问：他跟学长 · 甲有什么区别？**

> **小北管"怎么去"，学长管"是什么"。**
> "图书馆在哪" → 小北；"图书馆几点开" → 学长。
> 图谱里虽然存着开放时间，但那是**时间域**——**小北不碰**。

## 四、边界

### 4.1 与学长 · 甲

| | 向导 · 小北 | 学长 · 甲 |
|---|---|---|
| 管 | **空间**——在哪、怎么去、旁边有什么 | **信息与规则**——是什么、什么时候、怎么办 |
| **分界** | **位置与路径 → 他** | **时间、流程、规则 → 学长** |

**重叠区处理**：图谱里存着 `hours`（开放时间），但——

> **小北只答"在哪"，不答"几点开"。**
> 属性位在图谱里，**用的权力在学长那边**——**同一份数据，两个域，各管各的。**

### 4.2 与阿姨 · 丙、保安 · 老丁、学霸哥

| | 分界 |
|---|---|
| **阿姨 · 丙** | 小北管**食堂在哪**，阿姨管**值不值得去** |
| **保安 · 老丁** | 小北管**保卫处在哪**，保安管**我丢的东西** |
| **学霸哥** | 小北管**空间**，学霸哥管**知识** |

**"叫得动"的区分**（避免两个角色撞词）：

| 角色 | 说法 |
|---|---|
| **保安 · 老丁** | **叫得动来服务**（到场）——这个词留给他，**是他的身份标识** |
| **向导 · 小北** | 他**走过来带你**——不占"叫得动"三个字 |

### 4.3 记忆隔离

**小北记得你去过哪、问过哪，但其他角色不知道。**

**他不进社交网络**——对话内容、位置轨迹**一律不外传**。

## 六、独立交付与合体接口

**本角色按隔离开发：图谱与实现自包含，可独立开发、独立演示。**

### 6.1 交付件形态

**一个能独立跑起来的带路应用**——登录进去，问路，看镜头飞过去、看路径高亮。

```
向导/
├── index.html          登录窗口 + 聊天界面（单页）
├── app/                意图路由 / 别称解析 / 两跳 BFS / 路径转述
├── map/                **完整的校园地图**（现成资产）
├── data/
│   ├── graph.json      校园图谱：地点 + 关系 + 属性
│   └── alias.json      别称词典
└── server/             账号服务
    └── main.py         FastAPI：注册 / 登录 / 签发 token
```

**怎么跑**：

```bash
pip install fastapi uvicorn
uvicorn server.main:app --port 8000
# 再打开 index.html
```

**答辩时怎么演**（两句话动线）：

> ① 问「二食堂怎么走」→ **镜头飞过去、路径亮起来，配一句"过了图书馆右拐"**；
> ② 问「**我想找个安静的地方自习**」→ **问句里没有地名，他照样答得出来**。

**账号服务**：**轻后端**（FastAPI + SQLite）——注册 / 登录 / 签发 token。
**它不是登录 UI 的附属，是「记忆归属」的前提**：有了 `user_id`，你去过哪、问过哪，才能跨会话挂在**同一个人**身上。
**本交付件自带一套，独立可跑**；合体时五套并成一套统一账号。

### 6.2 合体接口

| 项 | 内容 |
|---|---|
| **自包含** | 图谱、别称词典、意图路由、空间推理、路径转述、地图——**全部在本角色内闭环**，不依赖其他角色的实现 |
| **唯一的外部约定** | **图谱与地图的节点对齐**（图谱的 `id` 要能落到地图的地点号上）——**是接口约定，不是实现依赖** |
| **合体方式** | 按总体设计 §2.2 的「工具集 + 人格配置」接入，对外暴露 `findRoute()` / `locate()` / `findPlace()` / `nearby()` |
| **合体后** | 引擎读 `tools` 知道他会干什么、读 `persona` 知道他怎么说话——**引擎一行不改** |
