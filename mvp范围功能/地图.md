## 一、第一阶段做什么

**室外已经做完了。第一阶段是给三栋楼做"里面"。**

一句话：

> **把「一张世界地图」变成「一张世界地图 + 三个房间」——而引擎的改动只有一个：把地面从常量变成变量。**

| | 现在 | 第一阶段之后 |
|---|---|---|
| 世界 | 一张，5208 × 2930 | **一张室外 + 三张室内**，各自独立尺寸 |
| 地面 | 常量 `groundCanvas` | **`scene.ground`**（当前场景的地面） |
| 碰撞 | 常量 `solids` | **`scene.solids`** |
| 切换 | 无 | **走到门口 → 切** |

**渲染主循环一行不改**——只把里面读的变量换了个来源。

## 二、现状（先说清楚起点）

### 2.1 已交付

| 件 | 状态 |
|---|---|
| `像素校园_全校地图.html` | **630,211 B**——完整室外校园，16 轮迭代 |
| 渲染主循环 | 地面烘焙 → 水面层 → 道具/角色按 `baseY` 深度排序 |
| 建筑生成器 | `makeBuilding()` ——**每栋已有窗、有门、有屋顶、有遮挡** |
| 交付件零依赖 | **全部美术是绘制函数**（`px()` / `poly()` / `circlePx()`），**没有一个外部图片文件** |

### 2.2 三栋楼在外面已经有了

按 §7 的换算链（1 英寸 ≈ 390.59 世界像素、1 米 ≈ 9.0 世界像素）：

| 楼 | PPT 尺寸（英寸） | 世界像素 | 约合 |
|---|---|---|---|
| **逸夫楼** | 1.6951 × 0.6118 | **662 × 239** | 73.6 × 26.6 米 |
| **计算机中心** | 1.1792 × 0.4854 | **461 × 190** | 51.2 × 21.1 米 |
| **校史馆** | 1.1792 × 0.2653 | **461 × 104** | 51.2 × 11.5 米 |

**所以第一阶段不建楼、不改外形、不动占位**——只做内部。

### 2.3 现在**没有"场景"这个概念**

渲染主循环是：

```js
ctx.drawImage(groundCanvas, ox, oy, ...)   // ① 地面：一次性烘焙，每帧 blit 视口
drawWater(ox, oy);                          // ② 水面动态层
// ③ 道具 + 角色：视口裁剪 → 按 baseY 深度排序 → blit
```

`groundCanvas` 和 `solids` 都是**模块级常量**——世界只有一个。**这就是第一阶段要动的那一点。**

## 三、三个室内场景

### 3.1 清单

| 室内场景 | 为什么有它 | 本文档 |
|---|---|---|
| **逸夫一楼** | **学霸哥的刷新点** | ✅ 展开 |
| **计算机中心** | **算法哥的刷新点** | ✅ 展开 |
| **校史馆** | 内容最重的一间，**要自己画美术** | ✅ 展开 |
| 食堂两层 | 阿姨的功能载体 | ❌ **不重复**，只做**机制对齐**（见 §4.5） |

### 3.2 逸夫一楼 —— 学霸哥的刷新点

**它得回答一个问题**：为什么学霸哥一直待在这儿？

| 空间 | 内容 |
|---|---|
| 入口门厅 | 进出、公告板 |
| **自习区** | 桌椅成排——**学霸哥就坐这儿** |
| 借阅/服务台 | 一个柜台，一个不动的 NPC 位 |
| 走廊 | 把三块串起来，也给玩家"逛"的余地 |

**这个场景的核心不是"楼"，是"座"**——玩家进来一眼要能认出"这是个能学习的地方"。

### 3.3 计算机中心 —— 算法哥的刷新点

| 空间 | 内容 |
|---|---|
| **机房** | 一排排机器 + 屏幕亮光——**算法哥在这儿** |
| 走廊 / 门厅 | 进出 |
| 一间小教室 | 备用的第二空间，让场景不是一条直线 |

**与逸夫一楼的区别必须一眼看出**：逸夫是**木色 + 纸**，这里是**冷色 + 屏幕光**。

### 3.4 校史馆

**三栋里最特殊的一栋**：它不是"功能房间"，是**内容空间**。

| 空间 | 内容 |
|---|---|
| 展陈区 | 展板 + 展品柜——**卡片文案的素材来源** |
| 序厅 | 一面时间墙 / 校徽 |
| 走廊 | 串起展线 |

**它一鱼两吃**（呼应 §22.5）：
- 校史馆本身就是"**到此一游**"玩法量最大的一个点位
- 展板的考据内容，直接就是**答辩时"我们做得有多细"的证据**

> ⚠️ **这里的"自己美术制作"我按"三栋都自绘、校史馆内容最重"理解**——
> 因为 `建筑物照片/` 里**这三栋一张参考图都没有**（只有南门和字体）。
> 若你的意思是"只有校史馆原创、另外两栋另有素材"，说一声我改。

## 四、场景切换：最小改动方案

### 4.1 现在

```js
// 模块级常量——全世界只有一份
let groundCanvas = ...;      // 烘焙好的地面
const solids = [...];        // 碰撞体
const props  = [...];        // 道具
const WORLD_W = 5208, WORLD_H = 2930;
```

### 4.2 改成

```js
const SCENES = {
  out:     { ground, solids, props, W: 5208, H: 2930, doors: [...] },
  yifu1:   { ground, solids, props, W: 1280, H:  768, doors: [...] },
  cscenter:{ ground, solids, props, W: 1280, H:  768, doors: [...] },
  musem1:  { ground, solids, props, W: 1152, H:  640, doors: [...] },
};
let cur = SCENES.out;        // 当前场景
```

渲染主循环**只把 `groundCanvas` 换成 `cur.ground`、`solids` 换成 `cur.solids`**。

**世界尺寸也变成变量**——这是必须的：室内比室外小得多，相机的 `clamp` 上界要跟着换。

### 4.3 门与出生点

**一张门表搞定两个方向**：

```js
{ scene: "out",  x: 3120, y: 1180, → { scene: "yifu1", x: 120, y: 600 } }
{ scene: "yifu1", x: 96, y: 620,   → { scene: "out",  x: 3120, y: 1210 } }
```

| 规则 | 为什么 |
|---|---|
| **门是双向的两条记录**，不是一个传送对 | 出门要回到**门口外侧**，不是回到门口里侧——否则会**立刻再触发进门** |
| 出门落点**外推一个身位** | 防止卡在触发圈里来回弹 |
| 进楼时**相机瞬间归位**，不插值 | 像素游戏没有"过场动画"这一说，硬切就是对的 |

**门的位置现成**：`makeBuilding()` 生成的每栋楼**已经有门**，只要把它记下来就行。

### 4.4 为什么**不做**独立 HTML / 独立页面

| 方案 | 否决理由 |
|---|---|
| 每个室内一个 HTML | **破坏单文件交付**；而且玩家进出要跳页面，**割裂感致命** |
| iframe 嵌套 | 同样破单文件，且通信要跨文档 |
| **同一文件 + 场景对象** | ✅ **改动最小、零新依赖、硬切无感** |

### 4.5 与食堂的机制对齐

食堂两层（阿姨.md §2.5 / §3.4）**走的是同一套场景机制**——它就是一个"两层的室内场景"。

| 谁定 | 什么 |
|---|---|
| **阿姨.md 定** | 食堂**里面长什么样**（档口、菜名、价格、评分可视化） |
| **本文档定** | 食堂**怎么被进出**（门表、尺寸、切换） |

**两边不重叠、也不冲突**——本文档只提供 §4.2 那个 `SCENES` 槽位，食堂**往里填自己的数据**。

## 五、跨文档接口：NPC 刷新点（**最要紧的一节**）

### 5.1 问题

学霸哥在逸夫一楼、算法哥在计算机中心——但 `agents/*.json` 里的点位**全是室外的**：

```json
"home": "library",
"schedule": [ { "at": "teaching_1", "from": "08:00", "to": "12:00" } ]
```

**室内点位没地方写。**

### 5.2 方案：点位 ID 带**场景前缀**

```json
"home": "yifu1:reading_room",
"schedule": [
  { "at": "yifu1:reading_room", "from": "08:00", "to": "12:00" },
  { "at": "out:canteen",        "from": "12:00", "to": "13:00" }
]
```

| 好处 | 说明 |
|---|---|
| **引擎统一** | 读点位时先切分前缀 → 决定在哪个场景找这个节点 |
| **零新字段** | 还是字符串，不改结构 |
| **可跨越** | 学霸哥中午去食堂**天然成立**——引擎知道要先出门再走过去 |

**没有前缀的旧点位**按 `out:` 处理 ⇒ **现有的五份配置一个字都不用改**。

### 5.3 影响哪些文档

| 文档 | 影响 |
|---|---|
| **学霸哥.md** | `home` 与 `schedule` 的室内部分要补前缀 |
| **算法哥.md** | 同上 |
| **向导.md** | **图谱的 `places` 要能装室内节点**——不然问"逸夫楼自习室在哪"，两跳 BFS **图上无此点** |
| **猫宠.md** | 猫**全在室外**，**不受影响**（领地本来就在校园里） |
| 保安.md / 阿姨.md | 保安全室外；食堂是阿姨的场景，用同一套前缀 |

> **向导这条最容易被漏掉**：向导文档 §3.1 的图谱数据模型是纯室外的。
> 室内点位如果不进图谱，**向导就带不了室内的路**——而"学霸哥在哪"是个高频问题。

## 六、美术：三栋室内怎么画

**三栋都没有参考素材**（`建筑物照片/` 里只有南门和字体），所以是**自绘**——但**不是从零**：

| 已有的 | 拿来干什么 |
|---|---|
| `px()` / `poly()` / `circlePx()` | 所有绘制的最小单元 |
| `rgb()` / `shade()` / `mix()` | 配色与明暗 |
| `shadowQuad` | 方向性阴影（服从 `SUN`） |
| 已有的**室内元素画法** | 桌椅、柜台的像素画法在食堂那份里已经趟过一遍 |

**三栋的视觉区分（一眼能认出来）**：

| 场景 | 主色 | 一眼睛特征 |
|---|---|---|
| **逸夫一楼** | 木色 / 米白 | 成排的桌椅 + 纸的暖调 |
| **计算机中心** | 冷灰 / 蓝 | **屏幕的亮点**——暗房间里一排发光方块 |
| **校史馆** | 深红 / 暖黄 | 展柜玻璃反光 + 展板的排布 |

## 七、交付件体积与性能

**这是本阶段最大的工程风险，先算清楚。**

| 项 | 估量 |
|---|---|
| 现在 | **630,211 B** |
| 三栋室内的**美术代码** | **绘制函数**，不是图片资源 ⇒ 每栋约 **6–12 KB** |
| 三栋室内的**数据** | 房间布局是代码里的数组 ⇒ 每栋 **2–4 KB** |
| 门表 + 场景管理 | **< 2 KB** |
| **预计交付件** | **约 660–680 KB** |

**结论：不必分片。**

**运行期内存**才是要看的：现在的地面是一张烘焙好的大画布（5208 × 2930）。三张室内各约 1280 × 768——**加起来不到室外的 15%**。

| 验收项 | 目标 |
|---|---|
| 首屏 | **仍 < 3s** |
| 帧率 | **稳定 60fps**（室内比室外还轻） |
| 内存 | 四张烘焙画布同时驻留，**仍远低于一张室外** |

> **不采用延迟加载**：室内地面可以在启动时就烘焙掉，多出的时间用户在几秒内感觉不到——
> **而换取的是"进门零卡顿"**。这个交换划算。

| # | 步骤 | 内容 | 产出 |
|---|---|---|---|

## 九、验收

| # | 验什么 | 通过标准 |
|---|---|---|
| 1 | **室外零回归** | 步骤 1 之后，**室外与改前逐像素相同**（同一相机位截图比对） |
| 2 | **进得去出得来** | 三栋各有门可进；**出门落在门外侧**，不来回弹 |
| 3 | **硬切无感** | 进出**无卡顿、无白屏** |
| 4 | **相机正确** | 室内相机 `clamp` 用**室内的 W/H**，不会滑到场景外 |
| 5 | **碰撞正确** | 室内墙体挡人、家具挡人；**门是唯一的出口**，不穿墙 |
| 6 | **三间一眼可辨** | **不看标签**，看画面就知道这是哪一间 |
| 7 | **NPC 落位** | 学霸哥**刷在逸夫一楼自习区**、算法哥**刷在计算机中心机房**——**进门就能看见** |
| 8 | **跨场景作息** | 学霸哥中午**从逸夫走去食堂**（引擎自动"先出门再走"） |
| 9 | **向导找得到** | 问"逸夫楼自习室在哪"，向导**能带路**（图谱里有这个室内节点） |
| 10 | **仍然单文件零依赖** | 交付件**一个 HTML**、体积 < 700 KB、无外部请求 |
| 11 | **性能不退** | 首屏 < 3s、稳定 60fps |

## 十、不在第一阶段

| 项 | 为什么推后 |
|---|---|
| **二楼及以上** | 垂直楼层要新的"楼层高度"与"上下楼"机制——**逸夫一楼是"一楼"，先把一层做透** |
| **室内光源/昼夜** | 室外的时间层要不要透进室内，是 §9 的问题，**室内先按常亮做** |
| **更多建筑可进** | 每加一栋就是一笔美术投入，**先证三个够用** |
| **室内小地图** | 有更好，但**不影响可玩性** |
| **食堂的实现** | **阿姨那份文档的活儿**（§4.5） |
