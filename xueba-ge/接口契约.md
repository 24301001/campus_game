## 2. 检索入口 `search()`（Python 签名，照抄）

```python
def search(self, query: str, *,
           course: str | None = None,
           source_type: str | None = "textbook",
           book: str | None = None,
           top_k: int | None = None,
           per_book: int | None = None,
           cross_book: bool = False,
           use_vector: bool = True, use_prior: bool = True,
           extra_terms: list[str] | None = None,
           exclude: set[str] | None = None) -> SearchReport: ...
```

返回值（dataclass → dict 两份都有）：

```python
@dataclass
class SearchHit:
    doc_idx: int          # 索引内部下标，别往外传
    chunk_id: str         # ★全局唯一出处 id，见 §4
    score: float          # 融合后总分
    norm: float           # 归一化 0-1，用来卡 min_norm
    paths: list[str]      # 命中路径：["bm25","vector"]
    ranks: dict           # {"bm25": 3, "vector": 7} 各腿名次，调试用
    snippet: str          # 带关键词的摘要
    rerank: float = 0.0   # 交叉编码器给的精排分。**和 norm 不是一个量纲，别混着当置信度**；
                          # 没开精排就是 0.0，`as_dict()` 里也就**不出这个键**（老消费方零改动）

@dataclass
class SearchReport:
    query: str
    hits: list[SearchHit]
    paths: list[str]          # 本次实际用了哪几条腿
    coverage: float           # 查询词被覆盖比例，<min_coverage 直接判低置信
    low_confidence: bool      # ★引擎/前端就靠这一个布尔决定要不要兜底
    reasons: list[str]        # 人类可读的拒答理由，直接进兜底话术
    elapsed_ms: float
    filters: dict
    terms: list[str]          # 本次真正用上的规范说法（已过词表闸门），没用到就是空
    dropped_terms: list[str]  # 模型补了但本库从没这种说法 -> 丢掉，前端要如实显示
    excluded: int = 0         # exclude= 传进来时，实际从候选池摘掉了多少条
```

**必须遵守的约定**（否则合体时总引擎没法统一兜底）：

1. **检索不到不许抛异常**，返回 `low_confidence=True` + `reasons`，让上层决定说什么。
2. `source_type=None` = 不限类型（跨库找资料时用）；默认 `"textbook"`。
3. `course`/`book` 命中不到任何切片时，`reasons` 里必须写清"该课程/资料类型下没有任何切片"，
   前端据此说"这门课我还没喂课本"，而不是"我不知道"。
4. **`extra_terms` 只许影响字面路**。它是大模型把学生口语翻成的教材规范说法（`准则`→`法则`、
   `夹着算`→`夹逼准则`），只能**追加**在 BM25 查询词后面：原话不许被改写，向量路、`coverage`、
   `unknown_terms` 这三处继续只看原话 —— 否则补一个词就能把"这门课没喂"洗成"喂过了"。
   入参前还要过一次词表闸门（`df>0`，复合词拆成分），过不了的进 `dropped_terms` 报给前端。
   生产这个参数的工具调用参数 `terms` 是**内部字段**，故意不写进 `config/tools.json`：
   那份文件是四个角色合体时的对外契约，不该为学霸哥的检索技巧多出一个键。
5. **`exclude` 是"进榜之前摘掉"，不是"排完名再删"**。传一批 `chunk_id`，引擎会先把它们从
   候选集合里去掉再排序，所以名次会补满。学霸哥的"同类往年题"卡片靠它避免和正文引用重复：
   事后过滤那种写法在候选池小的时候会**把卡片直接删空**（真向量上线第一天就撞上了，实测 0 条）。
   摘完什么都不剩时必须 `low_confidence=True` + 写明原因，不许静默返回空榜。
6. **向量的"来源"是契约的一部分**。`kb/index/meta.json` 里的 `embed_provider/embed_model/embed_dim`
   由 `embed.describe(cfg)` 写、由 `engine._align_vectors()` 在启动和热重载时核对：
   同源→放行；配置要 hash 而索引是别的→本地确定性重算；两边是不同模型→**抛错要求重跑 `kb.build`**。
   为什么这么狠：`doc_vecs.f32` 是裸 float32，**512 维的 hash 和 512 维的真语义模型字节数一模一样**，
   加载不报错，两套空间硬乘出来的"余弦"是噪声，而且分数会好看地骗人。
   另两条实测：`min_cos` 这类阈值**换一个向量空间就可能变成摆设**（bge 空间里「随手一条查询 ↔ 一片无关文档」中位余弦就有 0.604），
   服务商的 embedding 接口**不保证逐位可复现**（同一条查询连调 4 次，1 次 cos=0.9990）——
   所以这两个旋钮和评测数字都要绑定 provider 一起记录。
7. **放宽只放宽 `source_type`，不许跨课程**。低置信时上层会重查一次，课程过滤能不能放开，取决于课名是"谁说的"：
   用户原话或大模型点名的课 = 硬约束（认错了就回"这门课我没有"），检索分布自己猜出来的课 = 可以放开。
   反面教材实测过：四门示例语料下架后，「数据库四种隔离级别」被无条件放宽，结果引了《微积分上册》某页当出处。

## 3. 对话入口 `run()`（生成器，流式）

```python
def run(self, question: str, *, history: list[dict] | None = None,
        course: str | None = None, memory: str = "",
        from_image: bool = False) -> Iterator[dict]:
    """产出事件字典：meta / retrieval / citation / token / done / error"""
```

`agent.run()` 内部按顺序干四件事：**分类 → 选工具 → 路由选课 → 检索 → 生成**。
别的角色可以内部完全不同，但**吐出来的事件字典 key 保持一致**，前端一份代码就能服务四个角色。

**无资料降级（`config/agent.json` 里 `无资料时: "降级"`）有两条结构约定**，别的角色要做同款就照这两条抄：

- 那一次送给模型的 messages 里**根本没有【资料】块**（不是靠 prompt 劝它别编）。所以 `citation` 事件 0 条、
  正文里的页码不可能被编出来，`done` 带 `no_source: true` + `refs: []`，前端据此挂"无出处 · AI 记忆"灰牌。
  开关切回 `"拒答"` 就是任务书 §3.4 的字面口径，代码一行不用动。
- 校内事实类问题（"期末考什么""老师划的范围""图书馆几点开门"）和复习规划**永远不降级**，照常走兜底话术 ——
  模型不可能知道我们学校的情况，问它必然编。闸门就是 `agent.json` 的 `降级不许碰的问题` 加 `makeStudyPlan`。

**`from_image` 是"这句话的来路"，不是新的检索模式**（拍照/截图提问，见 README §2C）：
`True` 时只在用户那句话尾巴上多注一句"这是识别出来的、数字可能认错"，事件字典的 key、顺序、
`citation` 的算法一个字都不变。别的角色**不实现这个参数也行** —— 引擎多传的参数必须收得下
（`**_ignored` 也算收下），不能因为多一个 kwarg 就 500。

## 4. 出处 id 与页码锚点（★最容易打架的一条）

```
切片 id =  book_id # p<页码> # i<片序号>      例：net8#p105#i6
PDF 抽文本时每段前加一行                     [page:105]
```

- `book_id` 在**全项目组范围内唯一**，不要都叫 `book1`。建议 `<角色缩写><序号>`：
  `xbg-net8`（学霸哥·计算机网络第8版）、`ayi-canteen1`（阿姨·食堂资料1）。
  > 我现在库里是 `net8/os1/ds1/db1/campus/...`，合体前我会统一加 `xbg-` 前缀，**你们先用占位的，别急着定**。
- **`chunk_id` 含 `#`，所以绝对不能当 URL 的 path 参数** —— `#` 会被浏览器当锚点吃掉。
  我的做法是查询串传参：`GET /api/chunk?i=net8%23p105%23i6`。踩过的坑，别再踩。
- 引用不许编页码：`page` 只能来自 `extract.py` 抽出来的 `[page:N]`。没有文字层的 PDF 一律拒收并报警。

`kb/index/chunks.jsonl` 每行一条（字段名请对齐，多出来的字段引擎忽略）：

```json
{"id":"net8#p105#i6","course":"计算机网络","book":"…","book_id":"net8",
 "source_type":"textbook","chapter":"…","section":"…","page":105,"heading":"…",
 "kind":"para","text":"…","file":"net8.md","chars":412,
 "n_prev":"…","n_next":"…"}
```

`kind` ∈ `para | heading | table | caption`；`n_prev/n_next` 是相邻片原文，给模型补上下文用。
这两条有硬保证：**是邻居原文的逐字子串、`$` 成对、数学式外面不留裸宏和 HTML 标签**（按原子块裁，裁不干净就整条留空串），所以前端可以直接丢给 KaTeX，不会看到半行源码；`GET /api/chunk` 原样透传这两个字段。
`source_type` ∈ `textbook | past_paper | outline | campus_info`（**你们要加新类型先说，`source_prior` 要配权重**）。

## 5. `tools.json` schema（★引擎靠这个路由，一行不用改）

```json
{
  "namespace": "xueba_ge",
  "tools": [{
    "name": "askTextbook",
    "desc": "干什么",
    "when": "什么时候该调我（给引擎看的正例）",
    "not_when": "什么时候不该调我（负例，比正例更重要）",
    "params": { "question": {"type":"string","required":true,"desc":"…"} },
    "returns": { "answer": "string", "citations": "Array<{n,book,chapter,section,page,quote,chunk_id}>" }
  }]
}
```

**硬规则**：

- `namespace` 必填，工具名**在 namespace 下唯一**。总引擎调用时用 `xueba_ge.askTextbook`。
- ⚠️ **重名已经埋了一颗雷**：`学霸哥.md` §六 提醒过，算法哥有个 `makePlan()`，我的复习规划本来也叫这个，
  我改成 **`makeStudyPlan()`**。请组长把五个角色的工具名**汇总表拉一份**，撞了在群里喊，别等合体当天。
- `not_when` 请认真写。四个角色能力重叠（"数据结构大作业：判分归算法哥，报告归我"），
  引擎只看得懂 `when`/`not_when`，看不懂你们 README 里的段落。
- **多一种输入形态 ≠ 多一个工具**。学霸哥能吃图片，但 `tools[]` 还是三个：图在进入任何一个工具之前
  就已经被转成了文字（`POST /api/vision`），引擎不需要认识 `image` 这种参数。新开一个 `askPhoto()`
  只会让"这张图该归谁"变成引擎的多一道选择题 —— 别这么干。

我的三个工具：`askTextbook`（课本问答带出处）/ `explainProblem`（分步不给答案）/ `makeStudyPlan`（复习规划）。
完整定义见 `config/tools.json`。

## 7. HTTP 面（如果组长选"各起一个服务"的合体方式）

我的端点，其他角色建议照抄形状，前端零改动：

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/register` `{nick,password}` | 注册即登录，返回 `{token, user, session}`。`nick` ≥2 字 |
| POST | `/api/login` `{nick,password}` | 同上，401 = 昵称或密码不对 |
| GET | `/api/me` | 当前用户（token 校验） |
| GET | `/api/bootstrap` | 一次拿齐：`name`（界面显示名，读 `persona.json` 的 `显示名`）/ 用户信息 / 课程列表 / 语料对账单 `planned_courses` / LLM 状态 / **`vision`（拍照识别的开关与上限：`{available, provider, model, max_mb}`，前端据此决定 📷 按钮画不画）** |
| GET | `/api/sessions` | 历史会话列表（`session.id` 是 **16 位 hex 字符串**，不是整数）。**一条消息都没有的会话不出现**——新对话在本地是白板，第一个问题发出去时才由后端建会话 |
| POST | `/api/session/new` | 新会话 |
| DELETE | `/api/session/{sid}` | 删掉这段会话**连同里面的全部消息**，返回 `{deleted: true\|false}`；删别人的 → **403**（和读历史同一条串号防护），已经删过的再删返回 `false` 不报错。前端不需要先调 `/api/session/new`：`/api/chat` 的 `session` 传空串就会自动建，并通过 SSE 第一帧 `session` 事件把 id 回传 |
| GET | `/api/history?session=<16位hex>` | 某个会话的消息（含引用），每条 user 消息另带 **`src`**（`""`=手打 ／ `"photo"`=拍照识别出来的，重放时靠它把 📷 挂回去）和 **`image`**（拍照那条气泡上显示的**缩略图** data URL，`""`=没有；只当显示件，不进模型上下文） |
| GET | `/api/memory` | 这位同学的**跨会话画像**：`{memory, updated_at, paused, questions, due}` —— 侧栏「记忆」卡片读的就是它 |
| POST | `/api/memory/refresh` | 手动重算（同步，用户当场等得起），顺带把 `paused` 撤回 false |
| DELETE | `/api/memory` | 清空画像**并停掉自动归纳**；**历史消息一条不动**。"别记着我" ≠ "把聊天记录删了" |
| POST | `/api/chat` `{question, session, course, from_image, image}` | **SSE 流式回答**。`from_image: true` = 这句是图片识别出来的（可选，默认 false），只影响 prompt 里的一句提醒，不影响检索与引用；`image` = 那张题图的**缩略图**（前端压过，最长边 900 px、≤160 KB），只用来把这条气泡画成图，服务端 `vision.clean_thumb` 再核一道，**不合格就悄悄丢掉**（问题照答，绝不为了它打回 400）。带图这条请求体上限 2 MB，超了 **413**（读体之前就拦） |
| POST | `/api/vision` `{image}` | **图片 → 题目文字**（一次非流式多模态调用），返回 `{text, ms, model, mime, bytes, in_tokens, out_tokens, truncated}`。这个端点**只转写不作答** —— 作答是紧接着的一次 `/api/chat`（前端默认识别完就自动发，图片条上那个勾可关，README §2C）。`image` 是浏览器 `FileReader.readAsDataURL` 那一串 `data:image/png;base64,…`。错误口径：**400**=图片本身不行（格式不对／超过 `max_mb`／什么都没认出来／"这不是题目"），**413**=请求体超过 16 MB 硬上限，**502**=服务商那头出错，**401**=没带 token。**所有校验都在花钱之前**，图不行一次调用都不产生 |
| GET | `/api/chunk?i=<chunk_id>` | 出处详情（原文/页码/章节） |
| GET | `/api/health` | 索引规模、课程清单、provider、Key 是否就位、**`vision`（同 bootstrap 那份）**；另加两块：索引自报的向量来源（`embed_provider`/`embed_dim`/`vector_docs`，覆盖不到全片就是脏索引）和 **`rerank`**：`{provider, model, calls, failures, avg_ms, last_error}` —— **关着要能看出来是关着而不是坏了** |
| GET | `/models/...` | 端上/本地推理的权重静态目录（`MODELS_DIR`，默认 `models/`）。**目录不存在就不挂这条路由**，不影响其它端点。`.mjs`/`.wasm` 的 Content-Type 在 `app.py` 里显式钉死（Windows 注册表会把 `.mjs` 猜成 `text/plain`，浏览器会拒绝 `import()`） |

鉴权：`Authorization: Bearer <HMAC 自签 token>`。**不引第三方登录框架**，四个角色都用同一份 `auth.py` + 同一个 `data/.secret` 就能互认。

`/api/vision` 是唯一一条**请求体可能上百 KB**的接口，所以它有自己的一套上限（`config/llm.json` 的
`vision` 块：`model` 留空=跟着主模型 ／ `max_mb` 6 ／ `max_tokens` 900 ／ `max_chars` 4000 ／
`timeout` 45 s）。别的角色要做同款，记住两件事：**问题正文存的必须是转写出来的文字**（图只是显示件：要往消息上挂图，就挂一张压过的缩略图，别挂原图，也别让它进模型上下文），
**Key 只在服务端**（这条和 `/api/chat` 同源，浏览器永远拿不到）。

SSE 事件（9 个，`event:`/`data:` 格式）：


## 8. 会话隔离规则（"记住用户历史"到底记什么）

- 三张表（字段名以 `backend/db.py` 为准）：
  `user(id, nick, pw_hash, pw_salt, created_at)` — **用户名这一列叫 `nick` 不叫 `username`**，API body 也用 `nick`；
  `session(id TEXT PRIMARY KEY, user_id, title, created_at, last_at)` — id 是 16 位 hex；
  `message(id, session_id, user_id, role, content, tool, refs, created_at, no_source, src, image)` — 引用那一列叫 **`refs`** 存 JSON 字符串；`no_source` 是 0/1，标"这条是凭模型记忆答的"；`src` 是这句话的来路（`''`=手打 ／ `'photo'`=拍照识别出来的题目）；`image` 是拍照那条气泡上显示的**缩略图**（data URL，`''`=没有）—— **正文 `content` 存的仍然是识别出来的那段文字**，`context_messages()` 只选 role/content，模型看不见 base64；
  历史回放时靠这两个字段把灰牌和 📷 重新挂上（老库启动时自动 `ALTER TABLE` 补列，不用重建）。
- **`user_id` 是唯一隔离锚**。所有读接口必须先绑 `user_id` 再查 `session`。
- **越权返回 403，不是空数组**（实测已覆盖）：空数组会让前端以为"会话被删了"，403 才知道是权限问题。
- 上下文只取最近 N 轮（`llm.json.history_turns`，默认 6）塞给模型，**历史全量留在库里**，两者不是一回事。
- **"记住用户"其实是两层，缺一层就不叫记忆**：
  ① `session`/`message` = 原始历史（点开能回放、同会话内能接话）；
  ② `user_memory(user_id, text, updated_at, msg_count, paused)` = 从历史里**归纳**出来的画像（`backend/memory.py`）。
  只有①的话，点一下「＋新对话」就又失忆了 —— 那一层叫日志。②才是"开一段全新对话它也认得你"。
  画像每攒够 6 条新提问在**后台线程**重算一次（绝不在 SSE 中间等它）；没有 LLM Key 时退回规则版摘要，链路一致。
  注入位置在 system prompt 末尾，且明写"这不是资料、禁止当出处引用"——**记忆只决定讲多深，不决定讲什么**，
  引用永远只能来自检索。没有画像时 system prompt 一字不变（别把 prompt caching 的前缀弄脏）。
  用户可读、可重算、可清空（`/api/memory`），清空即停自动归纳。
- **MVP 阶段角色之间零交流**：学霸哥记得你问过什么，阿姨不知道。跨角色共享记忆是**下期**的活，需要组长先定 user 主键归谁管。

## 9. 合体方式二选一（请组长拍）

| | 方案①：总进程 import | 方案②：四个 HTTP 微服务 + 网关 |
|---|---|---|
| 延迟 | 工具调用 **≈0 ms** | 每跳 **+3–15 ms**（同机） |
| 部署 | 一台机一个进程，运维简单 | 各自独立发布，互不阻塞 |
| 耦合 | 四个人的 Python 依赖装一起，**版本冲突概率高** | 隔离，各管各的 venv |
| 统一鉴权 | 天然同一 token | 需要共享 `SECRET` 或网关换票 |
| 建议 | **演示/答辩用这个** | 真上线用这个 |

我的模块**两种都支持**：`backend/agent.py` 可以被 import（`Agent(engine, llm).run(...)` 是个生成器），
`backend/app.py` 是个标准 ASGI app 能被 `mount` 进总 FastAPI，也能独立起。**你们只要保证 §2/§3 的签名一致，三条路都通。**
