## 4. 标尺与坐标系（最关键的一节）

### 4.1 推导链

```
思源楼真实长度          ≈ 50 米                      ← 用户给定
思源楼在游戏里的宽度     = 450 世界像素               ← makeSiyuan 源码 BL=60→BR=360，宽 300 逻辑像素 × S=1.5 烘焙
思源楼在 PPT 里的宽度    = 1.1521 英寸                ← _shapes.json #5

⇒ 450 世界像素 = 50 米
⇒ 1 世界像素 ≈ 0.11111 米   (1 米 ≈ 9 世界像素)
⇒ 1 英寸 = 450 / 1.1521 = 390.59 世界像素
```

### 4.2 世界尺寸

```
PPT 幻灯片 = 12192000 × 6858000 EMU = 13.33333 × 7.5 英寸
WORLD_W = 13.33333 × 390.59 = 5208 世界像素
WORLD_H =  7.5     × 390.59 = 2930 世界像素
```

对比现状：`1408×960` → `5208×2930`，约 **3.7 × 3.05 倍**。

### 4.3 必备换算函数（写在文件最上方）

```js
const U = 450 / 1.1521;              // 390.5911 世界像素 / 英寸
const IX = v => v * U;               // 英寸 → 世界像素
const WORLD_W = Math.round(13.33333 * U);   // 5208
const WORLD_H = Math.round(7.5 * U);        // 2930

// PPT 形状 {x,y,w,h}（英寸）→ 世界像素矩形
const rc = s => ({ x: IX(s.x), y: IX(s.y), w: IX(s.w), h: IX(s.h) });
```

### 4.4 尺度交叉验证（说明标尺是可信的）

⇒ `U = 390.59` 得到三重印证，**不要自行改动这个标尺**。

### 6.3 渲染主循环（扩图后必须保留的骨架）

```js
const drawList = [];
function render() {
  const ox = Math.round(cam.x), oy = Math.round(cam.y);
  ctx.clearRect(0, 0, VIEW_W, VIEW_H);
  // 1. 地面底图：一次性烘焙，每帧只 blit 视口
  ctx.drawImage(groundCanvas, ox, oy, VIEW_W, VIEW_H, 0, 0, VIEW_W, VIEW_H);

  // 2. 动态图层（新增）：水面波纹 —— 在地面之后、道具之前
  drawWater(ox, oy);

  // 3. 道具 + 角色：视口裁剪 → 按 baseY 深度排序 → blit
  drawList.length = 0;
  for (const p of props) {
    const sx = p.x - p.ax, sy = p.y - p.ay;
    if (sx > ox + VIEW_W || sx + p.img.width < ox) continue;
    if (sy > oy + VIEW_H || sy + p.img.height < oy) continue;
    drawList.push(p);
  }
  drawList.push({ img: charSprite(player.dir, player.step), ax: CH_AX, ay: CH_AY, x: player.x, y: player.y, baseY: player.y });
  drawList.sort((a, b) => a.baseY - b.baseY);
  for (const it of drawList)
    ctx.drawImage(it.img, Math.round(it.x - it.ax) - ox, Math.round(it.y - it.ay) - oy);
}
```

**深度排序的语义**：`baseY = 物体"落地线"的世界 y`。
玩家 `baseY` 小于建筑 → 画在建筑之前 → 被建筑遮挡。这是"高度和遮挡"的唯一实现机制。

### 8.2 地面分类算法（核心）

PPT 只画了"有什么"（色块），**道路 = 剩余留白**。用"占用格 + 距离变换"自动推路网：

```
1. 建占用位图 occ[]，分辨率 CELL = 16 px
     NW = ceil(WORLD_W / 16) = 326
     NH = ceil(WORLD_H / 16) = 184        → 59,984 格
   对每个格中心 (cx, cy)：
     a) 若不在边界多边形内          → occ = OUTSIDE
     b) 若落在任一 CAMPUS 矩形内    → occ = 该矩形的 kind（bld / grass / water / track / bball / tennis）
     c) 否则                        → occ = FREE（待定）

2. 对 FREE 格做「到最近非 FREE 格」的距离变换（两遍 chamfer / BFS）
     d[] = 距离（像素）

3. 分类：
     d <= 2.5 * CELL  → ROAD（走廊）
     否则             → GRASS（开阔地，默认草坪）
   再叠加显式 ARTERY 矩形（§8.4）强制成路，避免主干道断头。

4. 道路分级（满足"宽度不固定、不硬归两档"）：
     W = d * 2                        // 该处走廊实际宽度（像素）
     W >= 100  → MAJOR 大路：沥青底 + 双黄中线 + 两侧路缘石 + 车道虚线
     W <  100  → MINOR 小路：砖 / 石板铺装，无中线
   ※ 宽度按 W 原样保留（不吸附到固定档），只决定「标线画法」
   ※ 边界处做 8px 羽化，让路沿与草地自然过渡（画两圈深浅不一的碎石边）

5. 开阔地（d 大）不铺路，铺草坪 + 随机树/花坛/长椅，避免"整片沥青"。
```

**为什么这样做**：PPT 里的建筑间隙天然就在 46 ~ 139 px（= 5 ~ 15 m），刚好是"小路 → 大路"的真实尺度。算法一跑，路网自然成型，还能得到用户要的"宽度不固定"。

### 8.5 建筑统一外形生成器

签名建议：

```js

  roof = '#7C8590',
  glass = '#8FB6D9',
```

绘制顺序（全部用 `px()` 硬边绘制）：

```
1. roofSlab：屋顶板。顶部一道 20px 深色檐口（roof 色 shade 0.8），

3. windows：窗阵——行 = floors，列 = floor((w - 2*margin) / (WIN_W + GAP))。
   单窗：外框 shade(wall,0.6) 1px → 玻璃 glass → 上 1/4 高光（shade(glass,1.25)）
        → 下 1/3 反射暗带（shade(glass,0.75)）→ 中间竖向窗棂。
   首层窗整体上移 30px，给门让位。
4. door：宽度 = min(70, w*0.18)；门楣深色，门内暖光（#E8C98A），
   两级台阶（墙下 8px 深的浅灰带）。
5. namePlate（可选）：楼名二值化文字，贴在门楣上方 8px。
6. edge：整栋楼外轮廓 1px shade(wall,0.55) 描边。
```

**锚点与碰撞**：
```js
const s = { ax: W/2, ay: H, canvas, x: cx, y: baseY };   // 底部中心锚
```

### 8.6 图书馆：切角 + 三角形石头广场

PPT #9 图书馆矩形：x 3080.0 → 3428.8，y 1016.9 → 1431.6（348.8 × 414.7）。

按用户口述"长方体被切一刀，切掉的三角区域是广场"实现：

```js
const L = { x: 3080.0, y: 1016.9, w: 348.8, h: 414.7 };
const cutX = L.w * 0.46;   // 160.5
const cutY = L.h * 0.42;   // 174.2
// 三角形广场（西南角）：
const plazaTri = [
  [L.x,          L.y + L.h],            // 西南角
  [L.x + cutX,   L.y + L.h],            // 南边切点
  [L.x,          L.y + L.h - cutY],     // 西边切点
];
```

- **建筑实体**（不规则体）用两个 AABB 近似：
  - `A = { x: L.x, y: L.y, w: L.w, h: L.h - cutY }`（上半，满宽）
  - `B = { x: L.x + cutX, y: L.y + L.h - cutY, w: L.w - cutX, h: cutY }`（右下）
- **立面视觉**：画在 `baseY = L.y + L.h`。左下角按 `plazaTri` 斜边"削掉"，
  即墙体的左下角是一条斜边（斜边下方露出广场石板）。
  斜边描一圈 3px 深色石材护角，强化"被切一刀"的观感。
- **广场**：写进 PLAZA，`kind:'plaza'`，多边形填充（石头铺装 + 深色石缘 + 中央一个小圆形树池）。
- **可通行**：广场三角区不加 solid；只在 `A`、`B` 两个 AABB 上加 solid。

### 8.7 水域：波纹 + 鸭子 + 鱼

PPT #3 水域：x 2738.2 → 3010.5，y 1016.9 → 1431.6（272.3 × 414.7）。

**静态底（烘焙进 groundCanvas）**：深蓝 `#2E6E9E` 底 → 由外向内 4 圈浅化（`#3B82B4 / #4A94C4 / #5AA6D2`）→ 随机亮色鳞光点。

**动态层（每帧绘制，在地面之后、props 之前）**：
```js
function drawWater(ox, oy) {
  const R = POND;                       // 世界像素矩形
  if (视口不相交) return;
  ctx.save();
  ctx.beginPath(); ctx.rect(R.x - ox, R.y - oy, R.w, R.h); ctx.clip();
  // 1. 横向波纹：正弦沿 x 平移
  const t = performance.now() / 1000;
  for (let i = 0; i < 14; i++) {
    const yy = R.y + (i * 31 + ((t * 9 + i * 7) % 31)) - oy;
    const amp = 2 + Math.sin(t * 1.3 + i) * 1.5;
    // 画一条 4~6px 高的浅色带（#9FD4EE，alpha 随 i 抖动）
  }
  // 2. 水岸亮线 + 内沿暗环
  // 3. 鱼：水下阴影椭圆缓慢巡游（只在偶发时刻露头 → 一圈扩散涟漪）
  ctx.restore();
}
```
- **鸭子**：作为 `props` 元素（`baseY = 鸭子的世界 y`），
  2~3 只，各自做 `x/y` 缓慢游动 + 上下 1~2px 浮动 + 朝向翻转（偶数帧 `flipH`），
  身后留 3 段逐渐变淡的 V 形水痕。
- **鱼**：水下暗影 + 周期性"冒泡涟漪"（3 圈扩散圆环，透明度衰减）。

> 动画全部走 `update(dt)` 更新状态、`render()` 读取，**不要用 `setInterval`**。

## 10. 环境与工具坑（血泪，务必先读）

### 10.1 文件写入受限
- **`Write` / `Edit` 只能写工作目录内**。写到 `%TEMP%`、桌面会被拒：
  `Access denied. Edit operations are restricted to the working directory.`
- 需要放桌面 → 先写工作目录，再用 `Copy-Item` 复制过去。

### 10.2 PowerShell 5.1 陷阱
1. **无 BOM 的 UTF-8 `.ps1` + 中文注释 = 灾难**：PS 按 GBK 解读，中文注释最后一字节 `0xA0` 会吞掉行尾换行，**把下一行代码并进注释**（实测 `$SX = $W / 13.3333333333` 整行消失）。
   → 脚本一律**纯 ASCII**（注释用英文/拼音），或存成带 BOM 的 UTF-8。
2. **函数名撞内置别名**：`function CAt()` 撞 `cat`（Get-Content 别名）→ 各种诡异报错。改名为 `PixAt` 即好。
3. **读 UTF-8 JSON**：`Get-Content -Raw | ConvertFrom-Json` 会乱码。
   → 用 `[System.IO.File]::ReadAllText($p, [System.Text.Encoding]::UTF8) | ConvertFrom-Json`
4. **终端输出被截断**：长结果写文件再读。
   → 写文件用 `[System.IO.StreamWriter]::new($p, $false, [System.Text.UTF8Encoding]::new($false))`

### 10.3 PPTX 解析
- `.pptx` 就是 zip，核心文件 `ppt/slides/slideN.xml`
- 坐标 `a:off x/y` + `a:ext cx/cy`，单位 EMU，**914400 EMU = 1 英寸**
- 填充 `a:solidFill/a:srgbClr val` 或 `a:schemeClr val`（可带 `a:lumMod`）
- 组合 `p:grpSp` 有 `a:chOff`/`a:chExt`，需做缩放换算
- **坑**：本文件建筑填充 XML 里是 `scheme:bg1`（= 白），但**渲染后实际是 `#D9D9D9` 灰**。
  → **必须靠渲染图取色**，XML 读不出真实色。
- **坑**：所有形状带 `accent1 lumMod 75000` 描边 → 渲染成 `#2E54A1` 深蓝，
  色块边缘会出现蓝像素，**别误判成水域**。
- 主题色（WPS）：`accent1 = #4874CB`（蓝，这才是水域色）、`bg1/lt1 = 白`、`dk1 = 黑`

**渲染 PPT 为 PNG（人工核对用）**：
```powershell
$ppt = New-Object -ComObject PowerPoint.Application
$pres = $ppt.Presentations.Open("D:\Desktop\校园示意图.pptx", $true, $false, $false)
$pres.Slides.Item(1).Export("D:\...\_map_render.png", "PNG", 2400, 1350)
$pres.Close(); $ppt.Quit()
# 若 WPS 环境则改用 KWPP.Application
```

### 10.4 浏览器自动化（`browser_evaluate`）
- `script` 必须是**纯表达式**：**禁止**手写 `(function(){...})()` 或 `return`
  → 用**括号包裹的箭头函数 + 逗号表达式**：`(() => (a = 1, b = 2, a + b))`
- 返回值 `text` 是 **JSON 字符串，里面又套了一层 `JSON.stringify` 的字符串**
  → 需要**双重 `JSON.parse`**
- 页面全局变量（`cam` / `player` / `props` / `makeSiyuan`）**可直接访问**；只有 `window.xxx` 才是 `undefined`
- `browser_take_screenshot` 在本环境**不可用**
  → 改用 `ctx.getImageData()` 采样，输出**字符画**来核验画面
- 中文文件名的 URL 编码会导致 http server 404
  → 复制/软链成 ASCII 名（如 `_preview.html`）再访问
