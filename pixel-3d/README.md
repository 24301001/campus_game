# 3D 像素小人模块 `pixel-3d/`

> 一句话：个人主页「形象预览」里那四张固定朝向的小图，换成一个**能用鼠标转 360°、
> 我的世界画风的体素小人**；发型 / 眼型 / 配饰 / 配饰染色这些控件照旧，
> 改的只是"配方画出来"这一步（另外多了一个「书包颜色」取色器，见 §7.5）。
> 全部代码只在这个文件夹里。

## ⚠️ 给做代码整合的同学：单独拿到这个文件夹是跑不起来的

本模块**只上传 `pixel-3d/` 这一个目录**，宿主侧的四处挂载点**不在这次提交里**，
需要整合的人自己加回去（缺任何一处，3D 要么不出现、要么 404）：

## 1. 怎么装进页面

```html

<!-- </body> 前，mp/look.js 之后、mp/lobby.js 之前 -->

```

```js
document.body.insertAdjacentHTML('beforeend', '<div id=t></div>');
Pixel3D.mount(document.getElementById('t'), null);   // 传 null = 用内置默认配方
```

## 2. 对外接口（`window.Pixel3D`，定义在 `pixel-3d.js:624`）

宿主要用本模块**只调这些**，别去碰内部函数。

### 2.1 挂载 / 卸载

| 接口 | 参数 → 返回 | 说明 |
|---|---|---|
| `mount(container, look, opts?)` | DOM 节点 + 配方 → **viewer** | 在容器里挂一个查看器。**同一个容器只挂一个**：容器上已有实例就只 `setLook()`，不重建 DOM（`pixel-3d.js:591`）。`container` 传 `null` 返回 `null` |
| `unmount(container)` | → `true`/`false` | 销毁该容器上的查看器并解绑 `rAF` / `ResizeObserver` |
| `create(look, opts?)` | → viewer | 只造不挂：返回的 `viewer.el` 还没进 DOM，尺寸量不到，**必须自己 `render()` 一次**（`mount` 里已经做了） |
| `renderTo(canvas, look, opt?)` | → canvas | 给一块现成的 `<canvas>` 画一张静态 3D（导出图片、自己拼缩略图用）。`opt.width/height/yaw/pitch/zoom/shadow` |
| `snapshot(look?)` | → `data:image/png;base64,…` | 无 DOM 离屏画一张 140×176 的正面图，直接进 `<img src>` |

`opts`（`create` / `mount` 通用）：

| 键 | 默认 | 作用 |
|---|---|---|
| `interactive` | `true` | `false` = 只留画布，去掉视角条和提示文字（`.p3d-static`），也不绑拖动/滚轮/键盘 |
| `autoRotate` | `true` | 进来就自转（`+0.42°/帧`）。用户拖一下、点一下视角键即停 |
| `yaw` / `pitch` | `-24` / `12` | 初始机位（度）。`pitch` 钳在 `-14..74` |
| `zoom` | `1` | 初始缩放，钳在 `0.6..2.6` |
| `shadow` | `0.32` | 脚下接地阴影的**透明度**。`false` = 不画（用于贴到别的底色上） |

### 2.2 viewer 实例

| 成员 | 说明 |
|---|---|
| `el` / `canvas` | `.p3d-root` 容器和里面的画布，宿主想改尺寸就 `el.style.setProperty('--p3d-h','320px')` |
| `state`（只读） | `{yaw, pitch, zoom, spin, look}` —— **验收脚本就看这个**，`look` 是规范化后的 12 字段配方 |
| `setLook(look)` | 换配方重画，**不动机位**（转好的角度不会因为改头发而跳回正面） |
| `setView(name)` | `front` / `right` / `back` / `left`，320ms 补间走**最短**那条路，顺带关掉自转 |
| `reset()` | 缩放回 1、机位回正面 |
| `render()` / `resize()` | 手动重画 / 手动通知尺寸变了 |
| `snapshot(type?)` | 当前画面转 dataURL（默认 `image/png`） |
| `destroy()` | 停 `rAF`、断 `ResizeObserver`、把 `el` 摘掉 |

### 2.3 只读工具（给别的模块复用，不碰渲染）

| 接口 | 说明 |
|---|---|
| `normLook(value)` | 任意输入 → 合法 12 字段配方（非法值一律回落 `FALLBACK`）。和 `MPLook.norm` 全等 |
| `FALLBACK` | 默认配方（`pixel-3d.js:39`） |
| `model(look)` | 配方 → 盒子清单 `[{name,x,y,z,w,h,d,faces}]`，想拿几何做别的事（碰撞、导出）用它 |
| `palette(look)` / `FACES` / `VERSION` | 调色板（6 档明度）、面名枚举、版本号 |

## 3. 操作方式（`interactive` 默认开）

| 操作 | 效果 |
|---|---|
| 按住左键左右拖 | 转体，`yaw += dx × 0.45°` |
| 按住左键上下拖 | 俯仰，钳在 `-14°..74°` |
| 滚轮 | 缩放 ×1.1 / ×0.9，钳在 `0.6..2.6`（`passive:false`，不会顺带滚页面） |
| 点「正面/右侧/背面/左侧」 | 补间到该机位并停掉自转 |
| 点 `−` / `+` / `复位` / `自转` | 缩放、回正面、开关自转 |
| 画布拿到焦点后按 `←→↑↓` | 每次转 15° / 抬 8°（键盘可达，`:focus-visible` 有金色描边） |
| `+` `-` `r` | 放大 / 缩小 / 复位 |

触屏走同一套 `pointer*` 事件（`touch-action:none`），单指拖动即转体。

## 4. 数据契约：12 个字段的 look 配方

这是**唯一**的输入。`mp/look.js` 那边能产出的东西，这里全部画得出来。

| 字段 | 取值 | 画在 3D 上的哪里 |
|---|---|---|
| `skin` | `#rrggbb` | 脸、颈、手的肤色（本模块内部再压出 3 档明度） |
| `hairColor` | `#rrggbb` | 所有头发块 |
| `hairStyle` | `short` `mid` `long` `ponytail` `bun` `twintails` | 后脑 / 两侧靠后的头发延伸；马尾、丸子头、双马尾是**背面才读得出来**的特征。⚠️ 凡是垂到下颌以下的发束，一律落在 `z ≤ -2` 那一档（和书包同层）——**胸前不许有头发**（自检第 6 组） |
| `eye` | `round` `narrow` `dot` | **只在正面**画（三档结构不同，不是同一形状改粗细）。侧面是块与脸成 90° 的真平面，一律不画眼也不画耳朵，整片是头发；圆眼还会把镜圈上沿抬高一行 |
| `eyeColor` | `#rrggbb` | 瞳孔（圆眼另带眼白） |
| `cloth` | `#rrggbb` | 上衣、袖子的主色 |
| `clothAlt` | `#rrggbb` | **只在 `clothPattern:'stripe'` 时**出现，是袖子上那道横条；`solid` 时不许进画面（自检第 7 组盯着） |
| `clothPattern` | `solid` `stripe` | 上衣条纹开关 |
| `pants` | `#rrggbb` | 双腿 |
| `acc` | `none` `glasses` `cap` `scarf` | 配饰。`none` 时**配饰那一族颜色一律不许出现在任何角度**（取下眼镜后眼部要干净，自检第 5 组） |
| `accColor` | `#rrggbb` | 配饰整体染色：帽身、围巾、眼镜框 + 镜腿都吃这一个色。眼镜的**镜圈高度还跟着 `eye` 走**（圆眼两行 ⇒ 圈从第 2 行起，细眼/豆豆眼一行 ⇒ 从第 3 行起） |
| `packColor` | `#rrggbb` | **常驻书包**的颜色（默认 `#b4552f` = 地图里那只）。高光/暗部由同一条 `shade` 式子现算，染成什么色就是什么明暗 |

## 5. 渲染是怎么做的（改几何/查问题前先看这段）

没有引任何 3D 库。整套是**体素 + 正交投影 + 画家算法**，全在 2D canvas 上：

1. **模型**（§4/§6，`pixel-3d.js:68`、`:255`）：小人是一批轴对齐盒子，坐标 `x=右`、`y=上`、`z=朝观察者`，1 个体素 = 1 个贴图格。盒子**故意互不插入**（自检第 10 组限定 ≤0.35 体素），因为画家算法只按盒子排序，插进去就会时对时错。
2. **面贴图**（§5，`:93`）：每个盒子 6 个面，每面产出一串 `[u, v, w, h, 颜色]` 矩形。共面贴合的两个面之间会发 `NONE`，不留缝。
   脑袋的**侧面**（`headSide`）= 前两列侧脸轮廓（额头 / 鼻尖 / 下巴，鼻尖在第 0 列）+ 第 2 列往后整片头发，**不留耳朵**。
   ⚠️ 侧面**不画眼睛**：瞳孔只长在正面那块平面上，转到 ±90° 时正面被窄面剔除 ⇒ 侧面读到的就是一块头发。
   ⚠️ 也**不留耳朵位**（第二轮实测："左右两侧不留耳朵位置了，把中间填上头发"）：2 格宽的耳朵嵌在整片发里读成
      一块色斑，紧贴侧脸皮肤又读成"脸上缺一格"，取掉之后侧面才是一块干净的发（也更接近我的世界那种"侧面就是头发"）。
   这跟四视图（`mp/look.js` 的 `headSide` 会留一只近眼）**是两套口径**，别照着四视图把眼或者耳朵加回来。
   **眼镜**走贴图不走方块（几根线宽做成方块会糊脸）：两只各 3 列宽的镜圈上沿 + 两条贴脸边缘的竖外框 + **一行**鼻梁，**不画下沿**（第 5 行是嘴）。
   ⚠️ 上沿一横贯脸宽就成了发带、鼻梁一占两行就成了脸正中一块斑、下沿一铺就等于给嘴染圈镜框色 —— 这三条都是实测报"眼镜显示混乱"的成因，自检第 5 组按行按列钉住了。
3. **投影**（§7，`:351`）：正交 ⇒ 一个轴对齐面投出来必是平行四边形 ⇒ **一个 texel 一次 `ctx.setTransform()` + 一次 `fillRect()`**，`BLEED=0.06` 抵消抗锯齿缝隙。背面剔除 `n[2] <= 0.0001`；窄面剔除（面在屏幕上压不满 1 像素就不画）。
4. **光照**：相机系固定光 `LIGHT = normalize([-0.34, 0.86, 0.38])`，`faceLight(n) = clamp(-0.06 + 0.32·dot, -0.30, +0.22)`，用一层暖/冷叠加矩形实现 —— 所以**转体时每个面的明暗会跟着变**，这是"看得出是 3D"的主要线索。
5. **排序**：按 4 个投影角的平均深度排，再按盒子序号（决定同深度时的先后）。
6. **取景**（§8，`:431`）：缩放按模型包围盒算，且**留了转满一圈都不出画的余量**（自检第 2 组：24 配方 × 24 偏航 × 6 俯仰 = 3456 个姿态，逐帧断言所有色块有限、在画布内、不退化成 0 面积）。

用 `node:vm` + 假 canvas（把 `setTransform`+`fillRect` 折回设备坐标矩形）+ 假时钟/假 rAF，

| # | 验什么 |
|---|---|
| 1 | `normLook` 与 `MPLook.norm` 在 810 组配方上**逐字段全等**（含 `packColor`） |
| 2 | 3456 个姿态：不出画、无 NaN、每帧都有东西 |
| 3 | 确定性 + 转满 360° 回到同一帧 |
| 4 | 眼睛/嘴在背面**和两个侧面**都必须消失；侧面逐格核对第 2..7 列 × 第 2..6 行**全是发**、第 0..1 列**全是皮肤**（不留耳朵位，也不许有配饰色） |
| 5 | 三种配饰戴上后各角度都读得出染色；`acc:none` 任何角度不许出现配饰色；**眼镜逐格核对**：镜圈上沿分成左右两段（中间两格必须空）、鼻梁只有一行、第 5 行（嘴）不许出现镜框、瞳孔一格不被盖、侧脸的镜腿只占一行 |

| 7 | 三档眼型结构不同；`clothAlt` 只在 `stripe` 出现 |
| 8 | 书包与上衣的前后绘制顺序**随转向翻转**（转到背面书包必须盖住上衣） |
| 9 | 颜色真的进了画面；**书包染 `packColor` 后正/侧/背三个方向都吃这个色**、且不泄漏到别的块；20 个配方画出 20 个不同签名 |
| 10 | 盒子不许互相插入（≥0.35 体素即失败） |
| 11 | 对外接口：`mount` 复用不打断视角、`setView('back')` 落在 180°、`unmount` 干净、`interactive:false` 无自转 |
| 12 | 每张贴图必须铺满所在面（不留空洞） |

改几何后**必须**跑这个；它不是快照测试，断的是"看得见"的性质。

### 7.5 第 12 个字段 `packColor`（书包颜色）：宿主侧要动的四处

本模块只认配方里的 `packColor`（默认 `#b4552f` = 地图里那只书包）。这个字段能不能存进库、
能不能出现在控件上，是宿主的事，整合的人要一起加：

| 文件 | 改动 |
|---|---|
| `mp/look.js` | `fallback` 加 `packColor:'#b4552f'`；`norm()` 的颜色名单加 `'packColor'`；`paint()` 里 `C` 的 `pack/packL/packD` 改吃 `v.packColor`（`shade` 用同一条式子、同一组系数 `.18/-.24`） |
| `mp/server.py` | `DEFAULT_LOOK` 加 `"packColor": "#b4552f"`；**`LOOK_COLORS` 元组加 `"packColor"`** |
| `mp/lobby.js` | 形象区加一个 `<label>书包颜色<input name="packColor" type="color" class="mp-field">`；`syncFields()` 和绑 `input/change` 那条 `for(const k of [...])` 数组**各加** `'packColor'`（两处是同一个数组，别只改一处） |
| 数据库 | **不用迁移**：`mp_player.look_json` 存的是整份 JSON 文本 |

⚠️ `LOOK_COLORS` 漏加**不会报错**：`valid_look()` 只拷贝名单里的键，`packColor` 被静默丢掉，
表现是"保存后重新打开永远是默认棕色"。改完 `mp/server.py` 必须重启进程才生效。

⚠️ 照片生成形象（`MPLook.fromPhoto`、服务端视觉模型）故意**不产出** `packColor`：
书包不是照片里能可靠认出来的东西，缺的键由 `norm()` 补默认值。

## 8. 怎么测（浏览器实测口径）

1. `.venv/Scripts/python.exe mp/server.py`（`PYTHONPATH` 要指到 `D:\Lib\site-packages`），或 `python -m http.server`；
2. 打开地图 → 登录 → 点「个人中心」→ 「形象」页签：`#mpLookPreview` 里出现的是**一个**带「正面/右侧/背面/左侧」按钮条的画布，不再并排四张小图；
3. 按住画布左右拖 → 小人转体，松手后**停在拖到的角度**（不会跳回）；滚轮 → 缩放；点「背面」→ 补间 180°，且**看不见眼睛和嘴**；点「右侧」/「左侧」→ 整块侧面只剩刘海 + 一片头发，**只有最前面两列是侧脸轮廓**（额头/鼻尖/下巴），**既不许出现眼睛，也不许留耳朵位**，要看见眼珠就得往正面转；
4. 换发型到「马尾」→ 从背面看到垂下来的辫子和发圈；戴「围巾」并把配饰色改成亮色 → 围巾吃这个色；上衣图案切「条纹」→ 袖子上出现 `clothAlt` 那道横条，切回「纯色」即消失；
5. 发型切「中发」/「长发」→ **正面不许有垂到胸前的两缕头发**：脸左右只露一点发边，整片发帘要转到背面才看得见；
6. 切「双马尾」→ 从背面和侧面看，两束扎在**耳后靠后**、和后脑那片发接成一片，垂在书包两侧；正面只剩脑袋两侧各一条，不在肩前；
7. 配饰选「眼镜」→ 正面读得出**两只镜圈**（两圈中间空两格，不是横贯脸宽的一条带子；鼻梁只有一行，不是脸正中一块），瞳孔一格不被盖住，嘴那一行不许有镜框色；转到侧面是一条镜腿 + 鼻尖那一列的镜圈边；
8. 「书包颜色」改一个亮色 → 3D 里**当场**变色（点「背面」最明显）→ 保存 → 刷新页面仍是这个色 → 地图上自己的角色**背向镜头**时那只书包也是这个色（这条走的是 `mp/look.js`，不是本模块）；
9. 把配饰从「围巾」改回「无」→ 任何角度都不留残色；
10. 收起「形象」页签再展开 → 画面立刻回来（`ResizeObserver`），收起期间 `rAF` 不空转；
11. 用 `Pixel3D.mount(...).state` 读 `{yaw,pitch,zoom,spin,look}` 可以脚本化验收。

## 9. 已知边界（不是 bug，改之前先读）

| 现象 | 原因 |
|---|---|
| 戴「帽子」时马尾的发圈、丸子头的发髻不出现 | 帽子和这两处头发占同一块空间，硬叠会插进帽子里（自检第 10 组）。所以帽子优先，马尾只留辫身 |
| 中长发 / 长发时围巾**不绕后颈**那一圈 | 后发帘本来就占那块地方，围巾只留前襟 + 两侧 |
| 背面看马尾会盖在书包上 | 辫子在书包更外侧，画家算法按深度排是对的；要"头发压在书包下"就得把辫子抬到书包上沿以上 |
| 小人**一直背着书包** | 书包是服装固定件，不是 `acc` 的一部分；`acc:none` 时它仍然在。**颜色可以染**（配方第 12 字段 `packColor`），但"戴不戴"没有开关 |
| 长发 / 中发 / 双马尾从**正面**看几乎不在身上 | 发束全部落在 `z ≤ -2`（脑袋侧面靠后）那一档，被手臂和躯干挡住是设计不是丢了 —— 放开到胸前就会重新长出"两缕头发糊脸"（实测报过） |
| 眼镜在 3D 上比四视图"重" | 8 格宽的脸上，两只镜圈 + 鼻梁就要吃掉 12 格，再画下沿就压到嘴。四视图那套只画 4 笔，是因为它有描边帮忙、且脸是 7 格 |
| 侧面的镜腿横贯整块侧脸 | 镜腿本来就从镜圈走到耳后，那一条线是对的；⚠️ 但它只许占**一行**（自检第 5 组按行数过），多一行就是老画法那条胶带 |
| 侧面（`yaw=±90`）**没有眼睛也没有耳朵**，和四视图不一样 | 侧面是一块与脸成 90° 的真平面，瞳孔只能长在正面那块上；转到 ±90° 时正面已被窄面剔除 ⇒ 侧脸只剩前两列轮廓 + 一整片发。耳朵当年画过一版，实测读成"整片发里一块色斑"，已按第二轮反馈取掉。四视图那种"侧视留一只近眼"是 2D 折中画法（`mp/look.js` 的 `headSide` 至今还这么画），**别照着它把眼或者耳朵加回来** |
| 缩略图（`interactive:false`）机位固定 | 没有布局可量，`renderTo` 用参数里的 `width/height`，默认 `-20°/12°` |
| 画布透明底 | 本模块不画背景，接地阴影在透明底上会读成一块浅灰。要底色就在容器上给 `background` |
| 极端缩放（`zoom:2.6`）会切边 | 取景按"转满一圈不出画"算，放大超出人身高时必然出框，这是放大的正常行为 |

## 10. 三轮实测的改动汇总（整合前请先读这张表）

对外接口从第一版到现在**一个字没变**（还是 `mount / unmount / create / renderTo / snapshot /
normLook / model / palette`，见 §2），变的全在"怎么画"这一层。下面每一条都是**实测判过**的口径，
想改回去之前先看它当初是怎么被否掉的：

| 轮次 | 实测反馈 | 落成的口径 | 钉住它的自检 |
|---|---|---|---|
| 一 | "左侧右侧应该全是头发，看不到眼睛才对" | 侧面不画瞳孔也不画嘴：瞳孔只能长在正面那块平面上（转到 ±90° 时正面已被窄面剔除） | 第 4 组 |
| 二 | "双马尾应该在侧面靠后的位置，跟后发接在一起" | 双马尾三块（扎带/发束/发梢）搬到 `z −4..−2`、贴住脑袋侧面，与后发帘同档共面相邻 | 第 6 组 |
| 二 | "中发和长发前面不应该有两缕头发" | 升成全局规则：**凡垂到下颌以下的发盒一律 `z ≤ -2`**，胸前不许有头发 | 第 6 组 |
| 二 | "眼镜显示混乱" | 镜圈重画成**两只**（上沿各 3 列、中间空两格）+ 一行鼻梁 + **不画下沿**（第 5 行是嘴）；圈顶行号按眼型走 `glassTop()`，正面和侧面共用同一个式子 | 第 5 组 |
| 二 | "给固定生成的背包也增加颜色自定义功能" | look 加第 12 字段 `packColor`；宿主侧要另动四处，见 §7.5 | 第 1 / 9 组 |
| 三 | "左右两侧不留耳朵位置了，把中间填上头发" | 侧面**取掉耳朵**：只留第 0..1 列侧脸轮廓（额头/鼻尖/下巴），第 2..7 列 × 第 2..6 行整片是发（三档发色，不再是平色块） | 第 4 组 |

### 10.1 预留接口：本模块已经能接、宿主目前只用了 `mount` 的那几个

| 接口 | 现在谁在用 | 还能直接拿来做什么 |
|---|---|---|
| `renderTo(canvas, look, opt?)` | 没人 | 名牌、公告行、私聊气泡想要一张 3D 小图：给块现成 canvas 就行，不用挂查看器。`opt.width/height/yaw/pitch/zoom/shadow` |
| `snapshot(look?)` | 没人 | 一行拿到 `data:image/png;base64,…`，直接进 `<img src>`、进聊天记录、做分享图 |
| `create(look, opts?)` | 没人 | 宿主自己控制 DOM（嵌进弹层、和别的控件共用容器），记得手动 `render()` 一次 |
| `model(look)` | 没人 | 拿盒子清单去干别的：碰撞、导出、给别的渲染器复用同一份几何 |
| `palette(look)` / `normLook(value)` | 没人 | 别的模块要跟小人同色系就取这一份，别自己再 `shade` 一遍；拿到任意脏配方先过一遍 `normLook` |
| `viewer.state` | 验收脚本 | 只读 `{yaw,pitch,zoom,spin,look}`，可以脚本化断言"转到背面确实转过去了" |
| `opts.shadow:false` | 没人 | 把小人贴到别的底色上时去掉那块接地阴影（画布本身是透明底） |
| `opts.interactive:false` | 没人 | 纯展示位：去掉视角条和提示文字，不绑拖动/滚轮/键盘，也不自转 |

数据契约那边还留着两个余量：`acc` 只有四档，但配饰是**整族吃 `accColor` 一个色**的，以后加"耳环 /
发卡"只要往 `acc` 枚举和 §5/§6 各加一块，宿主控件那行染色不用动；`packColor` 是同一个套路，再加
一个可染色部件（比如鞋子）就是照 §7.5 那四处复制一遍，**数据库仍然不用迁移**。
