# 食堂阿姨 · 独立交付

本模块独立运行，不需要接入全校地图，也不修改组内原有地图文件。包含账号、按账号隔离的多段对话、可用键盘或屏幕方向键操控的阿姨像素角色、食堂二维内视图、语音输入、来源明确的菜单与历史价格、口碑收集和排名接口。

## 启动

在项目根目录运行：

```powershell
python -m pip install -r aunt/requirements.txt
python -m uvicorn aunt.server:app --host 127.0.0.1 --port 8000
```

打开 <http://127.0.0.1:8000>。首次先注册。用户名为 2–24 位中文、字母、数字或下划线，密码至少 8 位。浏览器只记住上次的用户名，密码不写入浏览器本地存储；服务端登录会话有效期 30 天。SQLite 默认保存在 `aunt/data/aunt.sqlite3`，可用 `AUNT_DB_PATH` 更改。

## 资料状态

`data/canteens.json` 根据用户提供的食堂调研汇编录入学活、明湖、学四、留园、东区、学苑和益民的楼层、菜品与资料时段。`data/sourced_windows.json` 记录已能对应楼层的具体档口。`data/curated_food.json` 与新增的 `data/material_extract.json` 汇合为有来源的菜品线索；其中包含 2023 年校方公布的历史营业时段与 2024–2026 年菜品、个人消费记录。`material_extract.json` 另存的 308 条自动抽取价格候选没有进入当前菜单或报价，因为原文跨行匹配尚未逐条核对。历史记录均不表示今天在售或现价。

`data/plan_windows.json` 按用户提供的四张**“大概平面图”**整理学活二楼、明湖一楼至三楼的窗口、家具与入口相对位置。`data/oct10_updates.json` 补入学活一楼和修订后的明湖二楼，采用 32×20 格交互坐标；原图保存在 `static/plan-sources/` 供页面对照。两层使用高清插画底图，叠加可点击窗口和可操控人物；地图不显示价格，点窗口后在详情看逐菜价。图示楼层之外不绘制虚构档口，学活三楼因缺少图纸只展示资料线索。图中方位、尺寸和经营状态不能当作现场测绘结果；明湖一楼图没有北箭头，页面不会推定其东西南北。

学活一楼的 71 条图示价目从用户 PPT 中可辨的菜名与数字整理，标为“图示标价”。明湖二楼修订文档的 121 条明确金额记录中，只展示 103 条“图片可辨”的逐菜价格；另 18 条菜名字形待校核的记录暂不进入页面。截图价并非实时售价。`scripts/build_oct10_update.py` 可从项目内保存的明湖二楼修订文档重建结构化数据。

`floors[].stalls[].rect` 是内视图使用的 `[x,y,w,h]` 格坐标，`floor.plan.status` 标注 `approximate` 或 `illustrative`；餐厅级 `floorplanStatus` 仍为 `unverified`。目前没有现场测量的档口面积、全量窗口级菜单和实时经营信息。未来现场核对后，可修正格坐标并标记已核验状态；档口 `id` 应保持稳定，以免已有逐条评价错配。部分食堂有三层或地下一层，页面按资料显示对应层数。

补充材料的 2,930 行评论明细经筛查，整理出 `data/review_candidates.json` 中 58 条可追溯的逐条评价候选和 13 条楼层或餐厅口碑摘要。界面显示摘要及其原始链接；有明确同名窗口的评价才附在窗口详情。个体感受、平台总评数和自动抽取的评论不参与档口分数；没有可计算的用户逐条评价时显示“暂无评分”。

## 聊天与口碑

- 用户可问楼层、菜品、资料价、时段和公开口碑摘要；对无来源事实或校园其他领域明确说不知道。
- “学活二楼有什么面”等问题会返回带原文链接、来源日期和历史价标记的菜品线索卡片。推荐卡片随对话一起保存，不会根据资料摘要编造评分或当前菜单。
- 在对话中说“学四风味餐厅的麻辣香锅好吃，刚排了20分钟”，会记录分区、口味、排队时长、标签、时间和用户 ID，无单独打分表单。没有足够的窗口信息会请用户补充。
- 排队答复只看最近三小时的逐条记录。评分按 90 天半衰期计算；离线导入口碑的来源权重为用户评价的 0.35 倍。排名只覆盖已有逐条评分的分区，支持菜名与标签筛选。
- 各账号的对话和个人历史互不相见，口碑评分与评论属于所有账号可见的公共层。服务端提供 `/api/map-layer`、`list_windows()`、`get_rating()`、`should_appear()`，供以后合体时调用。

阿姨先从本地数据库生成答复，再调用 DeepSeek `deepseek-flash` 挑选与问题有关的事实片段；模型只返回片段编号，服务端拼接原文，所以模型不能另编菜名、价格或评分。请求失败时直接返回本地答复。设置进程环境变量 `DEEPSEEK_API_KEY` 即可启用，接口与模型可用 `AUNT_LLM_ENDPOINT`、`AUNT_LLM_MODEL` 覆盖，见 `.env.example`。密钥不要写入仓库或前端。聊天正文不显示来源链接，来源可在地图资料与档口详情查看。

## 离线导入可追溯评论

整理并去重、去个人信息后，准备 JSON 数组再运行：

```powershell
python -m aunt.import_reviews 已清洗评价.json
```

示例条目：

```json
{"stall_id":"xs-2-flavor","rating":4,"queue_minutes":20,"content":"香锅味道不错","published_at":"2026-09-20T12:00:00+08:00","source_ref":"https://example.edu/public/123","tags":["辣","排队"]}
```

导入器只读取本地文件，不抓网页。同一分区、内容、发布时间会跳过重复项。`rating`、`queue_minutes` 可分别为空，但至少要有一项。`source_ref` 可存公开原文链接。没有逐条正文时不运行导入器。

## 人物与界面

`static/pixel-aunt.js` 用 18×30 像素规格生成围裙、套袖、头巾角色，含四向、走动、呼吸待机和说话帧。`static/aunt-expressions.png` 是另行绘制的动漫风格对话阿姨，同一人物含平静、开心、思考、关切四种表情；聊天回复会切换表情。食堂内视图是独立的 32×20 格二维场景：可操控阿姨从入口出现，使用方向键或 WASD 上下左右移动，也可按住屏幕上的方向键；她不会自行来回巡走。墙、档口、桌椅等会挡住移动，视角跟随人物；滚轮、缩放按钮或 `+` / `-` 可以调整视野。每个图示档口后方另有固定值守人物，朝向和站位按档口矩形的前沿计算；她们与可操控阿姨是不同的场景角色。走近档口按 `E`、点“查看邻近档口”或直接点击档口，可以打开资料详情，并向当前窗口的阿姨提问。档口无逐条评价时保持“暂无评分”，不会从平面图推算评分；无法归属到某个窗口的菜品只放在本层线索列表。

聊天框旁的麦克风使用浏览器 Web Speech API（`SpeechRecognition` / `webkitSpeechRecognition`）。仅在支持该 API 的安全上下文显示入口；本机可用 `127.0.0.1` 访问。点击后浏览器会请求麦克风权限，识别结果先填入输入框，**不会自动发送**；用户核对后再发给阿姨。首次权限、识别服务网络情况及中文支持取决于浏览器。无法使用时仍可键盘输入。
