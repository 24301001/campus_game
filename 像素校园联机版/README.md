# 像素校园联机大厅（本地局域网版）

> **旧版样例，已停用。** 现在请在项目根目录双击 `启动像素校园.bat`，使用原有的 `像素校园_全校地图.html`。本目录的旧启动脚本也已改为转向根目录启动器。以下仅保留早期实验记录，不代表当前实现。

这是从 `像素校园地图项目/像素校园_全校地图.html` 复制出的独立多人版。原单机文件未修改。大厅包含同场景玩家互见、位置同步、场景切换、全服公告、在线和离线私聊、个人资料、照片本地取色生成像素形象。

## 启动

需要 Python 3.10+ 和 `websockets>=15`。首次安装：

```powershell
python -m pip install "websockets>=15,<16"
```

在本目录运行：

```powershell
python mp/server.py
```

本机打开 `http://localhost:3000/`。局域网其他电脑打开 `http://<运行服务的电脑的局域网 IP>:3000/`。HTTP 端口为 3000，WebSocket 端口为 8090；两端都要允许局域网访问。可用 `MP_HTTP_PORT`、`MP_WS_PORT`、`MP_HOST` 环境变量修改。每人用不同昵称注册，密码至少 8 位。服务将账号、消息与公告存进 `mp/lobby.sqlite3`；重启后仍保留。

双击 `像素校园_多人版.html` 可以进入单机地图；此时不连接大厅。关掉网关或临时断网时，已打开的页面继续保留地图操作并重试连接。

## 当前验收证据

运行 `python mp/test_smoke.py` 会启动一份隔离的临时数据库和三个独立客户端，检查：同场景出现、移动同步、跨场景隔离、全服公告、公告限流、私聊不串号、离线消息补收、个人主页字段白名单、昵称不可改、同账号后登录踢前登录。这个脚本只验证一台电脑上的三个客户端。

运行 `node mp/test_look.js` 会用合成像素区域检查黑发／金发、红色衣服、眼镜判定和 18×30 精灵规格。它不代替真人照片的现场测试。

界面已在浏览器中检查过：地图绘制、第二名玩家及昵称、公告发送和个人中心四向预览。照片只由 `mp/look.js` 在浏览器内解码与取色，服务端仅收发七个形象字段。

**至少三台电脑的现场验收尚未完成。** 有设备后，建议三台电脑在同一局域网分别注册甲、乙、丙，逐项实测：

1. 甲乙站在室外，同屏确认互见、连续走动；丙进入室内，确认不同场景不互见。
2. 甲在室内发公告，室外乙丙都看到；30 秒内再发一条，确认被拒绝。
3. 甲点乙的精灵开聊，确认输入框获得焦点，乙即时收到；丙确认看不到甲乙的聊天。
4. 乙退出，甲发离线消息；乙重新登录并打开聊天确认补收。
5. 甲乙上传不同照片，确认小人及公告头像对应，并用浏览器网络面板确认无照片上传请求。
6. 同账号在另一台电脑登录，确认旧连接提示并退出。

## 与二期任务书的差距

本目录实现的是可运行的本地大厅联调版。当前压缩包中的 8081 后端仍使用旧的用户名／邮箱注册模式，和任务书写的统一昵称账号、四家 NPC 换票方案不一致。因此本地大厅使用独立账号和 SQLite；还未接入 8081 的 `user.id`、MySQL 六表、四家 NPC 免登录，也没有完成 3D 躲猫猫／打牌匹配的跳转。上述项目不能算通过整份二期任务书验收。任务书指定的 Node.js `ws` + `mysql2` 网关可在主后端身份接口落地后替换本地网关；WebSocket 消息名称已按任务书保留。

照片特征识别采用浏览器内分区取色和简单的长发／眼镜启发式判断，提供手动调整与默认形象回退；没有接入任务书建议的 CLIP 模型。需要用不同发色、眼镜、衣服照片做实物验收。
