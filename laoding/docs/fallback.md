# 降级预案文档

> 保安 · 老丁 · 容错降级链与答辩预案
> 对应标准：《非功能 & 答辩交付质量》§1-2、§阻断级缺陷 2/4

## 一、降级链总览

```
云端 CV 在线（热机）
   │
   ├─ 以图搜物：CLIP 编码 → 余弦比对 → 图像相似度替换描述维 → top3
   ├─ 证件 OCR：PaddleOCR → 学号+姓名字段 → 双字段交叉验证
   └─ 零样本分类：照片先分路（证件→OCR，其余→以图搜物）
   │
   ▼  800ms 超时 / 断网 / GPU 关机
   │
降级层（主线不依赖 GPU）
   ├─ 以图搜物 → 降级为文字四维匹配（类别/地点/时间/描述）
   ├─ 证件 OCR → 降级为玩家手输学号 + 姓名
   └─ 零样本分类 → 跳过，直接走图像检索（再降级则文字）
   │
   ▼  仍不可用
   │
兜底层（纯本地，永远可用）
   ├─ 文字失物匹配：纯 CPU，零网络
   ├─ 报修工单：纯 localStorage
   └─ 证件核对：手输学号精确匹配（不依赖 OCR）
```

**核心原则**：主线单机模式不依赖 GPU 也可完整运行。云端是"锦上添花"，不是"命脉"。

## 二、各场景降级行为

### 场景 1：以图搜物 - 云端超时

| 触发 | `cvCall('encode')` 超时 / 网络错误 |
|------|------|
| 代码 | `toolMatchByImage` catch 分支 → `return { mode:'degraded', hits: toolMatchLostItem(query) }` |
| 玩家可见 | "云端图像检索这会儿不通（…）。已降级为文字匹配——这就是降级链的用处。" + 文字四维结果卡片 |
| 保障 | 功能不崩溃；文字匹配完整可用 |

### 场景 2：以图搜物 - 库内无图像向量

| 触发 | 库内失物 `vector` 均为 null（入库时云端未编码） |
|------|------|
| 代码 | `mode:'image_empty'`, `reason:'库内暂无图像向量'` |
| 玩家可见 | "库内暂无图像向量…。换个角度拍一张，或者用文字描述。" |
| 保障 | 不硬凑，如实告知 |

### 场景 3：以图搜物 - 库不存在该物品

| 触发 | 图像相似度全部低于 `thImage=0.30` |
|------|------|
| 代码 | `mode:'image_empty'`, `reason:'库里没有匹配物品——图像相似度全部低于阈值'` |
| 玩家可见 | "库里没有匹配物品…。换个角度拍一张，或者用文字描述。" |
| 保障 | 杜绝给库不存在物品硬凑 top3（阻断级缺陷 §4） |

### 场景 4：证件 OCR - 识别失败

| 触发 | `cvCall('ocr')` 超时 / 返回字段为空 |
|------|------|
| 代码 | `toolOcrCard` 抛错 → 流程转 `card_manual`，提示"直接把学号打出来" |
| 玩家可见 | "证件识别通道不通（云端未启动），你直接把学号打出来。" |
| 保障 | 证件查找退化为手输学号匹配（标准 §容错降级链） |

### 场景 5：OCR 低置信度

| 触发 | 字段 `confidence < ocrMinConf(0.6)` |
|------|------|
| 代码 | `toolOcrCard` 的 `ok()` 过滤掉低置信字段 → 该字段返回 null |
| 玩家可见 | "字段没认准（置信度不够的不参与判定）——宁可不判，不可误判。直接报一下学号和姓名。" |
| 保障 | 不强行判定，杜绝误认领（阻断级缺陷 §1） |

## 三、答辩预案

### 答辩前 10 分钟

```bash
# 1. 启动账号服务（主线，必须）
python server/app.py

# 2. 启动云端 CV 服务（GPU 实例上，如可用）
CV_TOKEN=xxx uvicorn cloud/cv_service:app --host 0.0.0.0 --port 9000

# 3. 预热模型（答辩前 10 分钟，避免冷启动）
curl http://<gpu-ip>:9000/warm
```

### 答辩中冷启动 / 断网应对

| 情况 | 应对 | 话术 |
|------|------|------|
| GPU 冷启动（演示以图搜物时卡顿） | 800ms 自动降级文字匹配，继续演示 | "这正是降级链的设计——云端不通，文字匹配顶上。" |
| GPU 完全不可用 | 跳过以图搜物，演示文字匹配 + 报修 + 手输学号认领 | "单机模式不依赖 GPU，核心业务完整可用。" |
| OCR 不可用 | 演示手输学号路径 | "OCR 退化为手输，双字段核对照样生效。" |

### 降级演示录屏（兜底）

如现场完全断网，播放预录 30s 视频展示以图搜物 + OCR 正常路径。视频内容建议：
1. 上传保温杯照片 → CLIP 返回 top3（10s）
2. 上传校园卡照片 → OCR 识别学号姓名 → 双字段核对通过（15s）
3. 口述"图像相似度替换描述维，其余三维照常加权"（5s）

## 四、GPU 运维策略

| 项 | 策略 |
|----|------|
| 开机 | 答辩前手动启动 + `/warm` 预热（冷启动约 2 分半：开机 90s + 模型加载 30s） |
| 释放 | 云平台设「无操作自动关机」（如 15 分钟无请求） |
| 热机单张耗时 | 约 100ms（CLIP 编码）/ 约 200ms（OCR） |
| 检索不占 GPU | 余弦比对在前端纯 CPU；GPU 只编码新图片 |

## 五、边界容错

| 输入 | 行为 |
|------|------|
| 地点别称（"一教""南大门""学活"） | `resolvePlace` 最长匹配，正确解析 |
| 乱码 / 无意义语句 | `classify` 返回 unknown → "没听懂。丢东西、找东西、报修——三件事，讲。" |
| 流程中"取消" | 任意流程中输入"取消/算了/退出" → 结束流程，"行。有事再讲。" |
| 空消息 | 不发送，不触发任何处理 |
